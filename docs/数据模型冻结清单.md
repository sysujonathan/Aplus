## 一、事实层

- 库文件：`workbench.sqlite3`（Windows 默认根 = `%LOCALAPPDATA%\Aplus\runtime`；旧版项目内数据自动兼容；`A_WORKBENCH_HOME` 可显式覆盖）
- 唯一 schema owner：`workbench/store.py`（文件头自述："The only owner of the new product's database schema; never opens old databases"）
- `schema_version = 4`（`meta` 表）。打开库时白名单校验 `{'1','2','3','4'}`，不匹配直接 raise
  "数据库版本与程序不匹配……不会自动清理数据"——**从不自动清数据**。
- `frozen_manifest.json` 不含 store（冻结的是 core/strategies 与配置）；但按既定架构，
  **GUI 阶段 store 也不动**。
- 共 **12 张表**：meta、datasets、jobs、events、observations、plans、plan_history、
  registry、validations、sync_coverage、scan_cache、watchlist。

## 二、核心关系（观察池链路全靠它，全部已存在）

```
watchlist(code PK ── observation_id)┐
                                   ├──> observations(id PK, dataset_id, payload JSON)
plans(id PK ── observation_id)─────┘         │
      │                                      └──> datasets(id PK, path, sha256)
      └──> plan_history(plan_id, payload)          （行情 CSV 在 root/datasets/ 下，
                                                     由 path 指向、sha256 校验）
```

- `watchlist`：`code TEXT PRIMARY KEY, observation_id TEXT NOT NULL, notes TEXT DEFAULT '',
  active INTEGER DEFAULT 1, created, updated` —— **一个代码一条**（重复关注走 UPSERT 换绑最新观察）。
- `observations`：`id, job_id, code, strategy, version, timeframe, asof, setup_date,
  dataset_id, payload(JSON), created`；索引 `(code, strategy, timeframe, asof)`。
- `plans`：`id, observation_id, code, strategy, timeframe, setup_date, state, entry, stop,
  target, quantity, notes, updated`。`id = sha256(code|strategy|version|timeframe|setup_date)[:24]`
  —— **同一信号只有一个计划**，重复保存是 UPSERT + 历史追加。
- `plan_history`：每次 `save_plan` 追加一条全量快照（seq 自增），天然就是**复盘时间线**。
- `datasets`：`id, code, timeframe, source, adjustment, start, end, rows, path, sha256, created`。
  `gui/data.py` 的 `load_dataset` 即沿 `observations.dataset_id` 取此表拿行情帧。

## 三、已经存在的写入口（GUI 侧直接调用，**不要自己写 SQL 增删改**）

| 方法 | 作用 | 内置校验 |
|---|---|---|
| `save_plan(observation_id, state, entry, stop, target, quantity, notes)` | 建/改交易计划 | 状态必须 ∈ `{观察, 计划交易, 已手工入场, 已手工退出, 忽略}`；价格与股数必须有限非负；`计划交易/已手工入场` 时强制 **0 < stop < entry < target 且 quantity>0**；写 `plans` + `plan_history` + event |
| `watch(observation_id)` | 加入关注 | 观察必须存在；UPSERT（换绑最新观察、重新激活） |
| `update_watch(code, notes, active)` | 改备注 / 结束关注 | 记录必须存在 |
| `write_artifact / read_artifact` | 运行目录内文件读写 | 路径越界即 raise；原子写（tmp+os.replace） |
| `rows / execute / event` | 只读查询 / 通用执行 / 审计事件 | — |

> `save_plan` 的校验就是风控约束（止损<入场<目标）在数据层的落点，**不要在 GUI 里重复实现一套**，
> 调用它、接住 `ValueError` 展示即可。

## 四、GUI 侧约定（本清单新立，属约定非既有事实）

1. `gui/` 对库**只读**：查询一律走 `store.rows()`（现状如此，保持）。
2. 需要写（关注、计划、状态）**只准调用第三节的方法**；禁止在 GUI 里 `CREATE TABLE`、
   `ALTER TABLE`、直接 `INSERT/UPDATE/DELETE`。
3. 观察池（P2）的读法：`watchlist LEFT JOIN observations LEFT JOIN plans`，
   一次拿到 `code / strategy / asof / state / entry / stop / target / notes`。
4. 若未来确需动 schema：只能在 `store.py` 内做，bump `schema_version`，
   配迁移说明与人工验收——**GUI 批次里禁止**。
