以下情况通常需要在定向测试之外运行完整本地回归：冻结策略或清单获批变更、数据库 schema 迁移、关键共享接口的大范围修改、依赖或测试基础设施变化，以及定向测试无法隔离影响。纯文档和确定无行为变化的普通格式调整可按 R0 做静态检查；CI 工作流的行为修改按 R2 或 R3 验证，其正式效果由 PR 的 GitHub 必需 CI 验证。

Windows 真实 Tk 用例若在当前 pytest 进程创建根窗口，使用 `native_process` 标记（含创建窗口的 fixture），由 `tests/native_process.py` 在 fixture setup 前隔离执行；已有独立子进程的用例无需重复标记。修改该测试入口时运行 `tests/test_native_process.py` 的失败传播探针及完整回归。连续失败的证据与适用边界见 [PR70桌面测试连续失败分析](PR70桌面测试连续失败分析.md)。

表中的 Python 测试使用 `python -m pytest -q <测试文件>`。两项 `.cjs` 回归不由 pytest 收集，应分别使用 `node tests/chart_tools_regression.cjs` 和 `node tests/chart_timeframe_regression.cjs` 执行。
