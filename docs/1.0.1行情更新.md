# 1.0.1：行情更新与扫描前核对

## 这次改了什么

**对账代替默认假设。** 以前同步完就直接扫描，现在扫描前先核对：市场应有 3000 只、本地日期就绪 2990 只，就明确报出 10 只缺口并**拦住整批扫描**，不再把 2990 当全范围。

界面会同时显示四个数：**应有 / 日期就绪 / 当日停牌不扫描 / 缺口**。
- 「应有」由数据源交易日历决定，周末节假日不强求新 K 线；数据源延迟发布也照样报缺口，不冒充成功。
- 「停牌」必须由同一交易日目录确认，不能因为没下载到就猜是停牌。

## 日常使用变化

- **顺序不变**：市场数据 → 日常扫描。本版首次使用先同步一次（取交易日历和当日目录），已有行情继续复用，**不用删库或重建**。
- **失败重试更省**：下载中断后再点同步，会跳过已覆盖部分只补缺口，不必勾「重新核验并刷新历史」。供应商黑名单或连续失败会止步，不无限重试。
- **目录突然缩水会被拦**：股票数量骤减会阻止覆盖，并把缺失代码写进运行记录（可能是接口不完整，也可能真是退市，需人工核对，不允许静默缩小范围）。
- **增量逐日核对**：新区间逐交易日核对，缺失日期必须有该次响应的停牌证明，否则不替换旧快照、不推进同步记录。
- **并发有限**：板块同步最多两条独立连接，每条复用会话，每个请求保留硬超时与停止能力。并行不等于固定倍数提速，需持续实测。

## 借鉴与保留

参考了本地 BPA Scanner 的 `fetch_universe.py`、`data_freshness_check.py` 和旧 A 的增量更新模块（**只读参考，不改这两个项目**），采用：增量复用、持久连接、有限并行、扫描前新鲜度检查、应有范围与实到范围对账。

**没有照搬**：BPA 的候选池过滤政策、识图/金榜流程、仅适用其主板池的固定价格跳变阈值；也不沿用「增量异常仍算 skip 成功」、仅靠线程 join 的超时保护、混接不同数据源复权价格。
**A 继续保留**：可杀死的数据源子进程、复权衔接核验、不可变快照、原策略冻结。

后续提速版进一步借鉴 TSP 的共享 enriched 数据与批量提交：同一股票的公共指标只计算一次，六个冻结检测器分别消费副本；同一股票的缓存、命中、事件和任务进度在一个 SQLite 事务中提交。历史快照存储结构没有改变，扫描与回测溯源保持原口径。

## 2026-10-03 日常链路提速

- 已覆盖股票不再把未变化 CSV 重新解析为 DataFrame；仍逐文件核验登记的 SHA-256，损坏文件继续拒绝复用。真实 300 份本机快照同环境基准：完整解析＋K线校验 **2.256 秒**，SHA-256 核验 **0.020 秒**，该局部路径约 **113.1×**。
- 同一股票启用多个策略时，300 根窗口的公共指标只计算一次。30 只真实股票、6 个日常策略同环境基准：重复指标 **11.220 秒**，共享指标 **7.765 秒**，纯计算段约 **1.44×**。
- 扫描缓存由逐策略查询改为单股一次批量查询；缓存、命中、审计事件和进度由逐项小事务改为单股一次提交。服务层文案或进度改动不再让策略结果缓存整体失效，缓存指纹只覆盖会改变计算结果的代码与冻结清单。
- 实测 4 线程策略计算为 **5.777 秒/60只**，反而慢于顺序共享计算的 **5.057 秒/60只**，因此没有照搬高并发；也没有把 BaoStock 从已验证的 2 条连接盲目提高到 8 条。

以上是局部真实数据基准与自动回归，不等于正式全市场长跑验收。首次运行新版本时，因计算语义指纹升级会重新计算一次；以后相同行情、日期、周期和策略版本可稳定复用。

## 准确边界（重要）

- 「日期就绪」≠「全部历史每根 K 线已认证」。本次检查**不会**自动证明旧缓存无内部缺口，也不能仅凭首根日期断定上市前无数据（需上市日期与历史停牌档案交叉核对）。
- 文件哈希与价格合法性校验仍在策略执行前运行，损坏文件不会交给策略。
- 新股历史仅 5 根，即便行情已最新，仍不满足扫描入口的 125 根要求 —— 这是**计算条件不足**，不等于「该下 125 根却丢了 120 根」。本次不改该门槛与核心策略。
- 日常扫描要求目录日期等于所选应有交易日，**不允许用今天的停牌状态解释历史日**。历史研究仍走回测；本版不提供历史成分股全集证明；CSV/演示来源不得冒用 BaoStock 全市场完整性结论。

## 文件与升级

| 文件 | 作用 |
|---|---|
| `workbench/readiness.py` | 交易日历、目录缩减保护、范围/日期核对、新响应缺口检测 |
| `workbench/sync_batch.py` | 最多两条独立连接、限制排队、停止后释放连接 |
| `workbench/store.py` | 路径解析/建目录/原子写入的串行保护（下载仍并行，避免 Windows 首次建目录竞争）；安全路径检查不放宽 |
| `workbench/service.py` | 同步收尾对账与后台扫描拦截（按钮禁用不是唯一防线） |
| `runtime/trading_calendar.json` | 最近一次获得的交易日历 |
| `meta.universe_date` | 目录核验日 |

不增加数据库表，不删除既有行情与结果。

**升级方式**：停止旧服务 → 双击桌面「启动A.cmd」。不要在同步或扫描运行中替换代码。runtime 不上传 GitHub。
