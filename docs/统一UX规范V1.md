# Aplus 统一 UX 规范 V1

版本：UX 1.0 · 2026-10-03 · 状态：首版规范，待交易员实际使用验证。

目标：让交易员快速找机会、判断风险、连续复盘，并能分清行情事实、策略计划、研究假设和自己的成交记录。

本规范适用于 Aplus Windows 桌面工作台；Web 调试入口沿用业务文案、状态和数据口径，布局按自身用途调整。V1 建立后续设计与验收基线，不代表现有所有页面已经完成改造。规范不扩大行情品种、策略权限或交易能力。

## 1. 使用方式与优先级

- 改页面前，先说明交易员要完成的任务、当前困扰、预计减少的操作，以及验收场景。
- 用户明确要求优先；业务边界以 [修改约束](修改约束.md) 为准；通用交互按本规范；页面特殊约定写在对应使用文档中。
- “必须”用于数据可信度、避免误操作及已有用户明确要求；尺寸、比例和耗时写作设计起点或验收目标，允许按真实窗口与反馈调整。
- 每次交付说明哪些规则已实现、哪些仍是建议。不要把规范文档或截图当作功能验收。
- 项目 skill 位于 [aplus-ux](../.agents/skills/aplus-ux/SKILL.md)，指向本规范，避免维护两套规则。

## 2. 四个工作场景

| 场景 | 交易员首先要回答 | 主要内容与操作 | 设计重点 |
|---|---|---|---|
| 盘前任务 | 今天哪些股票值得看？行情与扫描更新了吗？ | 选市场与周期 → 更新行情 → 扫描 → 多图筛选 → 关注／记录计划 | 多股比较、活动图明确、行情日与信号日分开 |
| 盘后回测 | 这套规则过去如何触发与结束？哪里赚、哪里亏？ | 选策略／范围／区间 → 回测 → 看机会和边界样本 → 逐笔复盘 | 可追溯结果、连续看图、完整性提示 |
| 策略迭代 | 本次研究改了什么，是否值得继续验证？ | 查看版本／条件 → 验证与真实研究 → 对比 → 人工决定是否启用 | 正式参数与研究参数分开、版本与样本条件清楚 |
| 交易管理 | 我的真实持仓与记录是否一致？现在承担多少风险？ | 看持仓／作战卡／清仓／绩效 → 录入或核对实际成交 | 金额与风险口径明确、输入可检查、记录可追溯 |

策略迭代中未接入的能力，只写为后续设计建议；现有界面不要放可点击的空功能或伪造研究结果。

## 3. 页面结构与空间分配

### 3.1 共用骨架

1. 顶部业务导航保持固定位置与顺序：盘前任务、盘后回测、策略迭代、交易管理。选中项清楚可见。
2. 页内依次放任务条件／操作、当前状态、主要工作区。历史与口径说明靠近它们影响的内容。
3. 同一任务控制区突出一个当前主操作，例如开始回测。查看、导出、设置等为次操作；不要让所有按钮同样鲜艳。
4. 辅助信息用侧栏、展开区或对话框承载；任务失败、结果不完整和涉及真实记录的校验问题必须直接可见。
5. 不重复显示页面名称、标的、日期或同一风险线来消耗空间；只在跨区定位确有帮助时重复。

### 3.2 按任务调整布局

| 页面 | 首选布局 | 可调整的设计起点 | 窗口缩小时 |
|---|---|---|---|
| 盘前 | 主图区＋右侧候选／关注；多图布局保持 2×2、2×3、3×3 选择 | 图区优先扩张，侧栏按内容设最小宽度 | 允许减少每页图数；不得擅自覆盖用户的布局选择 |
| 盘后结果 | 宽机会清单＋盈亏样本／分布侧栏 | 清单约占工作区 70%～80% | 盈亏样本可用两个标签切换，清单保持可复盘 |
| 逐笔复盘 | 大 K 线＋逐日事件侧栏 | 侧栏约 280～340 基础像素，图占剩余空间 | 收起研究条件；事件可折叠，保留事件日期与切换入口 |
| 交易管理 | 当前持仓、作战卡、清仓、绩效 2×2 | 延续已验收任务分区，重点表格优先可读 | 先处理表格滚动与辅助信息收纳，重排需场景验收 |

以上不是统一锁死的百分比。布局验收检查真实可用内容、列与按钮是否被挤掉，而非仅检查容器宽度。

### 3.3 窗口与显示缩放

- 基础验收窗口：1280×760、1600×1000、2560×1440；记录 Windows 显示缩放、字体缩放和实际图区尺寸。
- 100%、125%、150% 显示缩放分别检查，不能只在一个开发环境声称通过。
- 小窗口优先收纳次要内容；允许表格滚动，关键按钮、状态、标的与日期保持可达。
- 大窗口增加实际可见数据与绘图空间。字体放大以可读性为依据，避免单纯随屏幕宽度不断放大导致密度下降。
- Tk 字体需明确单位，避免系统点字号与自行缩放叠加；负数像素字号只是实现方式之一，必须通过实际显示验证。

## 4. 统一视觉基线

沿用项目石墨主题。颜色首先表达业务含义，圆角、边框与留白服务于分组，不添加装饰性渐变或大面积无内容卡片。

| 语义 | 颜色／基线 | 使用规则 |
|---|---|---|
| 页面／面板／输入／图底 | `#0D1117` / `#161B22` / `#1F2630` / `#10161E` | 对应 `gui/theme.py`，保持同层一致 |
| 正文／辅助文字 | `#E6EDF3` / `#9BA7B4` | 关键风险与失败信息不能使用弱对比灰字 |
| 边界／选中 | `#30363D` / `#253247` | 轻分隔；选中另有焦点或标题指示 |
| 主操作／焦点 | `#2F81F7` / `#58A6FF` | 蓝色用于操作与当前定位，独立于盈亏 |
| 上涨、盈利／下跌、亏损 | `#F04F5F` / `#20B26B` | A 股红涨绿跌；同时显示数值、符号或文字 |
| 待检查、覆盖不足 | `#E3B341` | 配“待扫描”“部分结果”等明确文字 |
| 中性、零值、未获得结果 | 正文／辅助色 | 零收益不强行归为盈利或亏损；未计算显示 `—` |

止损、目标、H1/H2 等已有策略绘图颜色保留各自语义，不因为通用红绿规则改成重复或相反的价位线。失败用文字与警示符号表达，避免仅用红色让人误认成盈利。

### 4.1 字体、间距与控件

| 项目 | 基础设计起点 |
|---|---|
| 中文与数值字体 | Microsoft YaHei UI ＋ Consolas；可选 Segoe UI ＋ Consolas；跨平台参考 Noto Sans CJK ＋ JetBrains Mono，不强制下载字体 |
| 字号 | 辅助 11～12、正文 13～14、区块 15～17、页标题 20～24、重点指标 26～30 基础像素 |
| 间距 | 使用 4、8、12、16、24；同组紧凑、组间清楚；页边起点 16 |
| 表格行高 | 默认 30～32 基础像素；紧凑 26～28，须交易员可读且可准确选中；行高与字号同步验证 |
| 按钮与输入 | 高度起点 30～36 基础像素；上下留白足够，中文与日期不截断 |
| 边框与圆角 | 1 像素轻边框；有圆角能力时起点 4～6；Tk 平面控件可不使用圆角 |

普通文本以 4.5:1、大字以 3:1 对比度作为检查目标，参照 WCAG 2.2；按钮上的文字也需检查实际前景／背景组合。上述色板不是任意搭配均合格的证明。选中、焦点、警告不只靠颜色区别，不声称已取得全应用无障碍认证。

## 5. 表格与指标

### 5.1 快速扫读

- 列按判断顺序排列：定位（日期、代码、名称）→ 价格／风险 → 结局／收益。交易管理按自己的记录与核对任务调整。
- 金额、价格、百分比与 R 在研究／账本表格优先右对齐；日期、代码、状态可居中；名称与说明左对齐。盘前紧凑候选保留现有居中约定，避免为了统一破坏多图浏览习惯。
- 单位放在列名或紧邻数值，不能让“风险 4.1”需要猜测是百分比还是金额。列名区分“价格风险”“账户风险”“风险金额”。
- 窄表允许名称省略，但须可查看完整名称；代码、关键价格、状态不得无提示截断。
- 排序须按数值／日期原值处理，显示排序方向；保持用户选择。V1 规定新增排序的行为，不假定所有现有表已支持。
- 表格筛选后的可见行与报告整体指标若不是同一口径，明确标注“筛选后 N 条”“本次回测统计”，防止误读。
- 保留选中、滚动位置和筛选上下文；数据刷新后原行不存在时明确说明，不能默默选中另一笔并执行操作。

### 5.2 指标口径

| 指标 | 必须表达的口径 |
|---|---|
| 机会数 | 当前策略／区间内纳入本次统计的机会；额外过滤排除数可在口径说明查到 |
| 触发率 | 已价格触发机会 ÷ 纳入统计机会；价格触发不代表成交 |
| 胜率 | 净 R 大于零的已结束交易 ÷ 已结束交易；未结束和未成交不混入；零收益不算胜 |
| 平均净 R | 已结束交易、扣除本次研究设定费用后的平均 R；注明样本数 |
| 初始风险中位数 | 已模拟成交样本的初始价格风险百分比；不称为账户风险 |
| Top 盈利／亏损 | 盈利取净 R > 0，亏损取净 R < 0；各最多五笔；并列按 H2 日期、代码稳定排序 |

以上描述当前 GAP H2 回放口径。其他策略或实际账本有不同口径时，写清自己的分子、分母和费用处理，不能直接套用。分母为零显示 `—` 及“暂无已结束交易”等原因；有效计算的零值显示 `0`，不伪装成缺失。

价格精度按交易品种 tick 确定，不能把所有 A 股相关品种写成 0.01。已确认股票 0.01、沪深 ETF／场内基金 0.001；未知品种不补造计划价。当前盘后执行回放仅支持已接入的 A 股股票日线，精度规范不等于扩大回测品种。R 通常保留两位小数、百分比通常两位；显示舍入不能反过来改变计算、排序或一个完整 tick 的突破要求。

## 6. K 线与逐笔复盘

- 图像按实际图区重新绘制，填满可用绘图容器；保留价轴、日期轴和成交量必要留白，不留固定缩略图居中造成的大块空白。
- 不靠裁掉轴、价格或标注，不靠拉伸固定 PNG 来铺满。窗口改变后重新布局与绘图；小窗口保留关键可读内容。
- 标题能定位代码／名称、周期、行情截止日；有历史锚点时区分原信号日与当前行情日。
- 多图蓝色活动标题只表示当前接收标的切换的图格；点击关注、拖入某格和翻候选组的行为延续已有约定。
- 引线端点对齐目标 K 线的水平中心；纵向落在所指价格／结构锚点，保留用户已确认的中心标注约定，不把高低点全部改成同一个纵向位置。
- 结构标注与每日计划标注分层，保留策略专属几何线、缺口区与 H1/H2；公共层不重复绘制策略自有风险线。
- 风险、SL1、Entry、MM／目标的口径一致；标注不能遮住当前关键蜡烛或互相堆叠得不可读。
- 逐笔回放默认仅显示所选事件日及此前行情；“完整走势（事后）”是显式模式，图上持续标明“事后”，切回后恢复截止日。
- 返回清单时保留报告、筛选、滚动和原选中样本。结果页与复盘页共用同一机会身份，不能返回后跳到另一笔。

## 7. 状态、空结果与提醒

任务状态、机会状态、实际账本状态分别显示，不共用一个含义不清的“成功／失败”。后端字段名称不因文案规范而重写。

### 7.1 任务状态

| 状态 | 交易员看到什么 | 下一步 |
|---|---|---|
| 未运行 | “选择策略与区间后开始回测”；结果为 `—` | 开始任务 |
| 进行中 | 当前阶段、已处理／总数、耗时；有真实进度才显示比例 | 可停止，可查看其他页面 |
| 完整完成 | 本次范围、截止日、完成数量和结果 | 看样本／口径／历史 |
| 没有机会 | “本次范围与区间未找到机会” | 调整条件；不能标为计算失败 |
| 筛选为空 | “当前筛选没有结果”；原报告仍保留 | 清除或调整筛选 |
| 用户停止 | “已停止 · 部分结果”，已完成数量 | 看已完成结果或重跑补齐 |
| 部分完成 | “部分结果”，失败／覆盖不足数量与影响 | 查看明细，再决定补行情或重跑 |
| 失败／重启中断 | 明确原因、可用的旧结果、处理入口 | 检查条件／数据或重跑 |

用户停止与运行失败不可混称。完整性标记在结果、复盘和导出中保留；保存下来的部分结果不会因为打开历史而变成完整结果。若尚无结果，不显示无依据的收益或示例统计。

### 7.2 机会与成交

| 情况 | 统一表达 | 价格与记录处理 |
|---|---|---|
| 可待挂 | “待挂”，说明计划对应哪一收盘日 | 展示该日计划价与风险 |
| 市场触发 | “价格已触发”；实际交易场景补“核对券商成交” | 不自动写入真实持仓，不继续冒充待挂 |
| 回放模拟成交／退出 | “模拟成交／模拟退出”；表内可简写，页面持续保留研究标识 | 与实际账本分开 |
| 失效／超时 | 写明状态和简短原因 | 隐藏可执行待挂价，保留历史记录 |
| 原形态无法复核 | “原形态无法复核，暂不提供待挂价” | 图上直接提示；保留原关注，不推断一定会随新行情消失 |
| 人工录入成交 | “已录入”或明确的买入／卖出记录 | 来源是用户确认的真实记录，不把策略触发当成交 |

日常提醒以图上信息区、相关行状态、任务栏为主。详细原因可展开；只有操作被阻止或真实记录需要核对时使用对话框，不新增外部消息发送。

## 8. 输入、范围与研究条件

- 市场板块名称与定义复用更新行情的主板／创业板／科创板／北交所，不维护第二套判断。
- 盘后默认四板块全选，只研究已有行情，范围按钮不追加“已存行情”；数据覆盖情况在任务状态与口径中说明。盘前保留自身已保存范围，不因切到盘后被覆盖。
- 关注名单是独立范围选择；当前回放约定不再用板块勾选暗中缩小关注名单。报告保存实际使用的范围，旧报告缺失信息时显示未记录，不能补造历史条件。
- 日期使用 `YYYY-MM-DD`，标签写“从／至”；起止不合法在对应字段提示，保留已输入内容。
- 高级设置只放当前策略可设置的研究参数，说明作用于本次／下次研究，不更改正式扫描参数。成交假设独立说明。
- 历史报告显示它运行时的参数、数据日期与版本；看历史不是重新计算，也不因当前控件不同改变旧报告。
- 修改输入、切页面和窗口变化不自动提交任务。未保存真实记录时，给出继续编辑／放弃修改的明确选择。
- 提交真实记录前展示标的、方向、数量、价格、日期和费用；错误输入在字段附近说明。破坏性操作说明对象与后果，按已有记录保留机制处理，不为普通查看反复确认。

## 9. 鼠标与键盘

| 所在位置 | 推荐行为／现有习惯 |
|---|---|
| 通用表单 | Tab／Shift+Tab 按视觉顺序移动；焦点清晰；Enter 不在输入时误触发任务 |
| 盘前候选列表 | ↑↓逐股；←→按当前多图布局整组翻页；单击切换活动图 |
| 盘后机会清单 | ↑↓选择；Enter／双击看图；另有可见“逐笔复盘”入口 |
| 盘后逐笔复盘 | 上／下一笔配可见按钮；图区／事件区 ←→切事件；Esc 返回结果 |
| 对话框 | Esc 关闭可取消对话框；有未保存真实输入时按放弃规则处理 |

快捷键只在对应工作区生效，不用全局按键绑定抢走日期输入、菜单或对话框按键。同一页面可见按钮与快捷键操作结果一致。滚轮只滚动鼠标所在表格／图区，触底不误滚另一个列表；页面切换不把焦点留在隐藏控件。

## 10. 响应与性能体验

- 点击后尽快显示已接收／加载状态；设计目标为约 0.2 秒内有可见反馈，需在实际机器计时，不能当作已实现承诺。
- 长任务展示阶段与真实计数，不假造百分比或剩余时间。已保存行情与复用结果的数量在回执可查；缺行情须说明。
- 后台计算期间界面可查看、选中、切页；停止先显示“正在停止”，收到回执后再显示“已停止”。
- 看图、缩放或选中高频操作可合并重绘、缓存，不能改变截止日、策略识别、成交假设或清除记录来换速度。
- 新报告运行中若展示上一份报告，持续标记“上次结果”，避免与当前进度混淆。缓存读取失败时给出处理状态，不把空白当正常零结果。
- 性能记录要附标的数、区间、机器、首次／复用和完整性；少量样本结果不外推成全市场耗时保证。

## 11. 开发落地与验收

### 11.1 每次改动交付四件事

1. 场景：交易员从哪里进入、要做什么、什么算完成。
2. 设计：主要内容、主操作、状态／空结果、键盘与小窗口处理。
3. 边界：会影响哪个页面；数据、策略、参数、真实记录是否变化。
4. 证据：代码测试、隔离真实数据检查、交易员实际使用分别写明。

### 11.2 必查情景

| 验收情景 | 通过标准 |
|---|---|
| 刚打开、没有行情或报告 | 明确下一步，无伪造价格／收益；无永久加载占位 |
| 更新行情后尚未扫描 | 行情日与信号日分开，明确待扫描 |
| 四板块多选、零选、关注名单 | 范围文案与实际输入一致；零板块阻止市场任务；不改另一页保存范围 |
| 启动、停止、失败、部分报告再打开 | 阶段和完整性一致；详细原因可查；旧记录保留 |
| 无机会、无已结束交易、筛选为空 | 三种原因分开；`—` 与有效零值分开 |
| 盈利／亏损边界样本进入复盘 | 表内样本与图中机会一致；事件日一致；返回保持位置 |
| 当时／事后、触发／成交 | 模式持续可见；未来行情不泄漏；触发不写真实持仓 |
| 真实账本输入错误、取消、修改 | 字段可纠正；取消不保存；修改结果与历史可核对 |
| 三种窗口与三种显示缩放 | 按钮可达、价格可读、图按容器绘制、滚动各自生效 |
| 只用键盘走一次主流程 | 焦点可见，顺序合理，快捷键不抢输入／隐藏窗口 |

自动检查与截图不能替代真实使用观察。每次选择与改动有关的情景验收，不为文字规范编写只匹配句子／标题的测试；涉及业务计算与输入保护时补有意义的测试。

### 11.3 交易员试用记录

建议首次试用记录三项：找出一笔 Top 亏损并看懂原因所用时间、连续复盘十笔的操作次数与返回定位情况、能否正确解释当前范围／日期／成交含义。不设未经基线测量的“提升百分比”。

V1 推进顺序：盘后页面按既有改造逐条对照 → 盘前统一状态和表格交互 → 交易管理统一输入与风险表达 → 策略迭代按真实接入能力展开。每一步经单独功能改动与验收，不因本规范自动启动全部页面重构。

## 12. 依据与当前落地状态

采用以下一手规范，并按交易工作台场景作项目化选择；没有引入它们的组件库或要求更换桌面框架。

- [NN/g：任务分析](https://www.nngroup.com/articles/task-analysis/)：按目标、步骤和实际工作方式安排流程。

- [Microsoft：Windows 键盘交互](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions)：焦点、键盘可达性与效率。
- [W3C：最低文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：文本可读性的检查目标。

本规范起草时（2026-10-03），盘后提速与布局分别在 PR11／PR12 待合入；相关实现与三种窗口工程截图是 V1 的对照样本，不是全应用合规证明。盘前与交易管理已有不同布局和点字号，未在此次批量修改。三种显示缩放全矩阵、全市场数据以及长期交易员体验仍需后续验收。
