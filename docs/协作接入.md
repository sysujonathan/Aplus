# Aplus 协作接入指南（给协作者）

> 业务安全约束见 `docs/修改约束.md`，执行和测试选择见 `AGENTS.md`、`docs/Codex执行规范.md` 与 `docs/模块测试地图.md`。
> 一句话版本：**GitHub 是唯一事实源；改动只在分支上做；按风险验证；正式 PR 必须通过 CI；main 只经 PR 合入。**

## 0. 前置条件

| 项 | 说明 |
|---|---|
| GitHub 账号 | 仓库主人（sysujonathan）在 Settings → Collaborators 邀请你后，邮箱接受邀请 |
| Git | 装 [Git for Windows](https://git-scm.com/download/win)（带右键 Git Bash）或 GitHub Desktop |
| Python 3.12+ | 装 [python.org](https://www.python.org/downloads/) 版本，勾选 Add to PATH |

## 1. 首次接入（一次即可）

```bash
git clone https://github.com/sysujonathan/Aplus.git
cd Aplus
setup.cmd          # 建虚拟环境 .venv 并装依赖
.venv\Scripts\python.exe -m pytest -q
```

首次接入用完整测试确认环境可用。测试数量随仓库变化，以当前执行结果为准；失败时先诊断环境或代码原因，不带着未解释的红灯开工。

## 2. 日常迭代循环（每次改动都走这个圈）

```
① git pull                          ← 开工先同步，防止落伍
② git checkout -b 名字/主题          ← 建自己的分支（如 zhang/fix-watch-panel）
③ 改代码（让 ChatGPT/Codex 打开本地文件夹干活，它会自动读 AGENTS.md 守约）
④ 按 docs/模块测试地图.md 运行定向测试；高风险或影响难隔离时跑完整测试
⑤ git add -A && git status          ← add 后扫一眼清单，确认没夹带敏感文件
⑥ git commit -m "Aplus：改动摘要"
⑦ git push -u origin 分支名          ← 推的是自己的分支，不是 main
⑧ GitHub 网页开 Pull Request，描述写四件事：
   改什么 / 影响哪个场景 / 不应改变什么 / 怎么验收的
⑨ 等仓库主人 review 合并；CI（Actions）自动复检，红了按日志修
```

### push 的两种操作方式（第 ⑦ 步）

**命令行**：在仓库根目录（`Aplus` 文件夹，有 `.git` 的那层）地址栏输 `cmd`：

```bash
git push -u origin 分支名        # 第一次推新分支，-u 建立跟踪
git push                        # 之后同分支再推，直接两个字
```

**GitHub Desktop**：左下角 `Commit to main` 改成你的分支名 → Commit → 顶部 `Push origin`。
（Desktop 里先 `Current branch → New branch` 建分支。）

### push 被拒怎么办

| 报错 | 含义 | 处理 |
|---|---|---|
| `rejected ... fetch first` | 远端有别人的新提交 | `git pull` 后重推（遇冲突见下） |
| `Your local changes would be overwritten` | 本地未提交改动与远端重叠 | 先 commit 自己的，再 pull |
| 冲突标记 `<<<<<<<` | 两边改了同一处 | 让 AI 辅助解、你确认，再 commit + push |

## 3. 红线（违反会被 CI 或仓库主人拦下）

- ❌ 默认不改 `core/strategies/`、`frozen_manifest.json`；只有用户明确点名授权某一策略升级时，才可限于该策略文件同步版本、获批记录、校验值与测试，不能顺带修改其他策略
- ❌ 不直接 push main（只经 PR）
- ❌ 不提交 `.workbuddy/`、`runtime/`、密钥、持仓等隐私内容
- ❌ 不 `git push -f` 强推
- ❌ 不在 PR 里夹带与本主题无关的改动

## 4. 用 AI 干活的正确姿势

- **ChatGPT 桌面版 / Codex CLI**：打开本地 `Aplus` 文件夹——它会自动读 `AGENTS.md`，冻结约束自动生效。
- **ChatGPT 网页版**：适合讨论与审查（贴文件/贴报错），别让它凭空改代码——它看不到仓库。
- 改完让 AI 按风险运行定向测试；高风险或影响难隔离时再跑完整 `pytest -q`。正式 PR 还必须通过 GitHub 必需 CI。

## 5. 分工建议

- 同一文件尽量只由一个人改（比如你动 `gui/`、对方动 `workbench/`），冲突概率趋近于零。
- 每次开工前查看 GitHub 活动 PR、负责人和计划修改的共享文件；已有同类任务时优先协作、评审或复用，不重复实现和重复开 PR。
