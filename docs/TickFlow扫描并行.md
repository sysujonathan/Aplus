# TickFlow 扫描作业内并行

日常 TickFlow 更新完成后，未缓存的原生策略计算按股票分给有界的本机计算进程。每只股票仍使用原有完整快照校验、周期转换、最近 300 根指标和冻结检测器；命中、计划价格、评级、异常、机会身份与缓存键不变。不改变 TickFlow 请求、限速、复权和行情保存，也不改变 BaoStock 替补流程。

默认按 CPU 和可用内存选择最多 8 个计算进程：不超过逻辑 CPU 的一半，预留 1 GiB 给桌面与主服务，每进程按 512 MiB 预算。少于 64 只待计算股票、资源不足、研究插件、自定义原生参数或已有生效的五策略快拒控制器时保持原扫描路径。并行能力不授予、不续签、不替代快速拒绝授权；Service 源码变化仍可能按既有规则使旧快拒绑定失效。

子进程只读取不可变行情并计算，绝不建立 Store、写 SQLite 或请求供应商。最多保留两倍 worker 数的在途任务；重复快照在非强制扫描中只预取一次。主服务按原股票和策略顺序消费结果，消费前仍走原行情读取与 SHA-256 校验，防止预取后文件被修改。未就绪股票仍排除，未知缺日不当作停牌，回测和账本不参与本能力。

每股原有耐久事务和回执重建保持不变。取消会终止本任务的计算进程，预取完成但尚未提交的结果不计入进度，重试复用已经提交的判断。计算进程启动、通信或退出异常时，收起本轮进程池并从当前股票恢复原串行计算；业务计算异常仍在原股票、原策略位置报告，不会变成无信号。

Windows 安装版通过自身的 `--scan-worker` 私有入口启动隐藏计算进程，不打开重复桌面或首次引导。正式构建增加离线的真实 windowed EXE 管道检查，包含真实 H2 待挂命中、中文异常、子进程退出和源数据库不变。

维护时可在启动软件前设置 `APLUS_TICKFLOW_SCAN_WORKERS=1` 回到串行；`2` 到 `8` 是上限，仍受 CPU/内存限制。默认 `auto`；无效设置安全使用串行。此设置不改变行情或策略结果，不清除缓存。正常回执的 `execution` 可记录实际进程数及基础设施回退原因；已有完成阶段直接复用时不会创建进程池。

性能必须分别核对行情更新、完整性核验和全部策略完成的时间。进程启动、原逐股提交和每股公共指标仍有成本，不能按核数直接承诺倍率；本 PR 不声称缩短 TickFlow 更新阶段，也不把首批结果出现当作全量扫描完成。
