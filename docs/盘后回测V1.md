# 盘后回测 V1：GAP H2 历史执行回放

桌面「盘后回测」现在可以选择日期与已存股票日线，运行原 GAP H2 的历史机会回放。现有 Web 固定价回测保留。此入口独立于盘前任务，不产生观察记录、关注记录或人工计划。

## 交易员使用

1. 在盘前任务完成行情更新，进入盘后回测，选择日期及全市场已存行情／关注名单。
2. 高级设置只调整本次 GAP H2：突破观察窗口、最短／最长回调、H2 后等待期限。风险上限与最低 MM R 是额外筛选，0 表示关闭；在 H2 成立日检查，不改变盘前正式策略。
3. 开始回测。统计区只看机会数、触发率、已结束胜率、平均净 R、已成交初始风险中位数。检查触发、成交、已结束与未结束的数量，并检查覆盖提示及失败。
4. 筛选机会结局，双击一行或按 Enter 看 K 线。右侧 Top 盈利／Top 亏损也可进入复盘，各取最多五笔已结束交易，按扣费后 R 排序；并列按日期、代码、机会标识稳定排列。
5. 复盘默认从 H2 成立日开始，只显示所选事件当时及之前的数据。左右键切换事件，上下键切换当前清单中的机会；返回保留筛选和位置。「完整走势（事后）」明确允许看后续行情，但不改变回测输入。
6. 通过历史回执切换已保存结果。报告记录行情快照及校验、策略版本、研究条件、成交假设、起止日期、研究范围与失败项目，重启后可读取。

## 执行口径

- 每一个候选收盘日只把当时可见的最近 300 根行情交给冻结指标和策略。必要的 LHLL、BO、回调期限及缺口／MM 条件在当时原始价格上预筛选，以减少不可能成立日期的重复计算；已纳入的同一 BO 不重复计算。预筛选不是额外研究筛选，不排除原策略可成立的形态，最终 H2 仍由原策略确认。仅纳入研究区间内首次确认的形态，区间前已成立的待挂机会不追加入样。
- 原形态的 BO／H1／H2／缺口／MM 在首次确认时固定；计划与盘前共用 `project_plan`，次日 Entry 为最新高点加一个品种 tick，SL1 为 BO 后最低点减一个 tick。原默认参数及原策略文件不变。
- 当前桌面服务只接受已确认 tick 与 T+1 的 A 股股票。ETF 等品种暂不进入此执行入口；不会用股票 tick 或结算规则替代未确认品种。
- 价格触发与成交分开记录。同日既触及计划价又发生结构失效／MM，无法确认先后，保守不成交；归为对应 MM 先达或触发未成交，并保留触发观察。无成交的结束机会不显示当前待挂价，历史计划仍可复盘。
- 停牌（零量）或单一价格 K 线不模拟成交／退出，不能证明涨跌停排队和流动性。入场遇跳空取计划价与开盘价较高者再计滑点；入场价已经达到 MM 时拒绝成交。
- 买入当天按 T+1 不卖出。当日触及 SL1 且开盘已在入场价之上，下一可交易日开盘延迟止损；买入当日达到 MM 不兑现利润。若盘中先触及 SL1 或入场无法确定，保守不成交。
- 成交后 SL1 与 MM 固定；后续同日双触碰按止损。跳空止损按较差开盘价，跳空止盈只按 MM；到持有期限时在可交易日收盘退出。报告尾端未结束仓位不强平。
- 净 R 分母为实际模拟入场价减 SL1，分子为扣除双边佣金、卖出税费与滑点后的每股盈亏。默认成本是假设值，可以在「成交假设／回执」调整下次参数，不构成实时费率保证。
- 机会可重叠，不是资金曲线、复利或组合表现。Top 盈利仅取 R > 0，Top 亏损仅取 R < 0；未成交、未结束与零 R 不进入两个清单。

## 数据完整性与保存

只使用新 Aplus 数据仓登记的不可变行情快照。全市场明确指已存范围，未保存股票不在统计分母内；关注名单有缺失快照时不能开始。演示源禁止进入；导入 CSV 可研究但来源未经行情源认证，不作为真实行情验收证明。

已有交易日历用于判断区间末端，避免把休市日当作缺数。没有日历时不推断停牌，覆盖不足会提示；开始日前不足 124 根预热也会提示并标为部分完成。历史前复权快照不是严格的当时数据版本，当前名单有幸存者偏差。

输出为既有 jobs 回执和运行目录 `research/<任务编号>/` 下的 report.json、replay.json、trades.csv，以及 `research-cache/h2/` 下已完整回放标的的研究缓存，不新增数据库结构，也不写交易管理的账户、真实成交、持仓、持仓成交或清仓记录。停止时只保存已完整回放的标的，标为已停止；失败或覆盖不足标为部分完成，不能冒充完整报告。旧报告、用户记录和源行情均不删除。

## 回放提速与重复研究

第一次运行先排除不可能成立的日期，仍逐日调用原指标和原策略确认候选；不把全段预计算指标交给策略。预筛选只使用截至该日的原始高低价，允许参数所需的价格范围最多 242 根，完整包含在原 300 根计算窗口内。引擎保留关闭预筛选的工程对照入口，不作为交易员参数。

相同行情快照、研究区间、GAP H2 条件、成交费用、原策略及回放程序版本会自动复用每个已完成标的，包括零机会的结果。源行情仍每次读取并校验，损坏不能因已有缓存而跳过；缓存有校验值，损坏则重新计算。行情版本、任一研究条件或程序／依赖版本变化会换用新键重新计算。升级前的旧报告不直接当作缓存。停止后再次提交相同条件，已完成标的可复用，未完成标的从头回放；历史已停止回执不会改成完整。

进度显示已完成标的及复用数量，最多约每 0.35 秒写入一次进度，结束时立即保存最终状态。完成回执显示回放耗时与复用数量；报告的耗时不含最后写报告的时间。缓存只保存研究结果，不改变正式观察、计划或交易管理记录，不新增下单能力。

## 验收范围

结果清单表头与内容使用相同对齐方式，价格、风险与净 R 右对齐。固定价格列不随大屏平均拉宽，多余空间由名称和结局列承接。状态、统计说明及事件说明按实际可用宽度换行。侧栏保留五笔盈亏样本，R 分布随剩余高度铺开，不再重复列出柱状图已有的六组计数；不改报告及统计口径。

自动测试覆盖动态计划与默认正式计划一致、一个 tick、固定原形态、不读未来、触发与成交分离、同日歧义、T+1 延迟止损、费用与 R、等待期限、额外条件、Top 样本、回执和盘前数据隔离。Windows 桌面测试覆盖 1600×1000／1280×760 比例、筛选、复盘切换和返回定位。

真实行情验收用 `python -m tools.acceptance_h2_replay --source-home <新Aplus数据仓> --home <独立验收目录> --start YYYY-MM-DD --end YYYY-MM-DD --codes sh.600000 ...`。源仓只读，校验快照后复制到独立目录；不打开旧项目数据库，不向用户正式表写入。少量真实行情工程验收不证明全市场表现或策略优势。

性能对照可用 `python -m tools.benchmark_h2_replay --source-home <新Aplus数据仓> --home <独立验收目录> --start YYYY-MM-DD --end YYYY-MM-DD --limit 24`，选择已有 H2 档案关联的真实股票快照，对比预筛选前后完整逐笔记录与事件，再对比首次和重复研究结果；验收目录生成 benchmark.json。样本包含已结束与未结束机会，但不是全市场代表性抽样，不把其倍率推广为全市场耗时保证。

长期实际使用、全市场长区间耗时及交易员逐笔核对仍需要实际使用验收；不把代码测试或少量真实行情回放当成长期验收。
