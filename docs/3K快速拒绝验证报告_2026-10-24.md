## 等价性证据

### 多日期真实行情

使用源仓只读 BaoStock 快照，300 只股票、5 个历史交易日，共完成 1,493 次合法前缀对拍：

- 快速拒绝：970 次；
- 门禁通过、执行原版：523 次；
- 完整 payload 或机会身份差异：0；
- 门禁拒绝但原版出正式信号：0；
- 原版业务异常：0；
- 熔断：0。

这五个固定横截面没有 3K 正式信号，因此不能单独作为充分证据。

### 真实正式信号专项

为避免“零信号零差异”，另对 1,211 只真实股票的可见历史信号行进行搜索，并按信号当日重新截断行情、重新准备指标和正式 payload：

- 原计算窗口候选行：66；
- 按当日前缀可复现的正式信号：60；
- 60 个正式信号全部满足门禁必要条件；
- 完整 payload、日期、Entry、SL、TP、评分和机会身份误拒绝：0。

其余 6 行在按当日前缀重算后不再是正式信号，原因是当前 300 根窗口与当时输入窗口起点不同；没有把它们冒充正式命中。

### 合法生成数据与异常语义

300 份、125—300 根合法生成 OHLCV 未发现门禁拒绝但原版出信号的反例。代码测试另覆盖：非法价格、日期错序、公共指标改变 OHLCV、阳线指标不一致、ATR 文本污染、指标无穷值／缺失／有限错值、版本或环境变化、缓存及熔断实现变化、旧授权失效、原版业务异常、差异熔断、缓存隔离和 BaoStock/TickFlow 双源。

2026-10-25 根据人工审查补齐安全闭包：`scan_cache.py` 的实际哈希、Store 的连接／事件／序列化及 `meta`、`events`、`scan_cache` 表契约进入绑定和精确白名单；EMA20、ATR、实体／影线占比及收盘位置按同一 OHLCV 逐列复算；阳线标志必须是无缺失的布尔列。无关的回测历史函数变化不再误停 3K，但上述持久化契约的任何变化仍会使旧授权失效。

同轮复审还明确分开 CANARY 与 ACCELERATED：CANARY 比例表示获准进入新快速路径的样本比例，ACCELERATED 比例表示保留原版核验的样本比例。比例 0、1 和中间值均由确定性测试覆盖，两种模式不再执行相同分流。上述修复均使旧绑定自动失效，生产仍默认 OFF，重新授权仍需人工审批。

对齐 PR #66 合并后的 main 后，3K 专项 **34 passed**；3K、MTR、扫描适配与冻结清单 R3 定向回归合计 **157 passed**。这里是代码测试，不替代新 head 的 GitHub 必需 CI、全可扫池 SHADOW 或长期实际使用验收。

未在真实行情中观察到原版业务异常；真实异常等价仍属于静态审计和受控测试证据。CANARY/ACCELERATED 未抽样拒绝样本仍存在与 MTR 同类的理论异常时点差异，因此正式启用前必须先完成目标全池 SHADOW。

## 性能

### 3K 检测器局部模型

人工审查加固后按相同 300 股、5 日口径重新测量：1,493 次真实前缀的原版 3K 累计为 26.232 秒；包含六项公共指标完整核对的门禁累计 3.746 秒。按 970 次拒绝直接跳过、523 次门禁通过后执行原版计算，预计为 12.940 秒，局部减少 **50.67%**。

这是基于逐样本实测组成的检测器模型，不是 Service 墙钟。

### 六策略真实短历史 Service

60 只真实短历史、六个策略、三轮交错顺序：

| 模式 | 冷扫描中位数 | 相对 OFF | 业务摘要 |
|---|---:|---:|---|
| OFF | 10.255 秒 | 基线 | 一致 |
| SHADOW | 10.352 秒 | +0.95% | 一致 |
| ACCELERATED（隔离授权） | 9.723 秒 | **-5.19%** | 一致 |

三轮绝对值仍会受机器噪声影响；SHADOW 因完整执行原版并增加核对应略慢于 OFF。可信结论是该 60 股样本中 43/60 被安全拒绝、3K 原版调用减少 43 次，六策略墙钟中位数约改善 5.2%。它不是全市场或一键盘前承诺，也不与 MTR 的历史百分比直接相加。

## 正式启用前条件

1. 在最终合并后的 main 和目标 Windows 环境重新生成绑定号。
2. 对正式质量门禁后的全可扫池运行 SHADOW，并逐股核对目标日期有效性。
3. 补充真实 TickFlow、约 2,800 根长期仓和多交易日持续运行。
4. SHADOW 保持零差异、零熔断后，另行申请小比例 CANARY；生产默认仍为 OFF。
5. 任何可信差异或原版异常立即停止启用申请并保留证据。

## 与其他策略 PR 的关系

本 PR 不依赖其他未合并策略加速，但各 PR 都必须最小修改 `workbench/service.py`。PR #66 已先合并；PR #67 随后对齐最新 main、保留双方系统地图条目并重新生成了绑定。PR #66 的 Service 变化按设计使旧授权失效，而其 Store 中无关回测历史方法变化没有再误停 3K。后续任何其他策略 PR 改变 Service 时，仍须重跑 MTR 和已合入策略专项，并重新生成所有受影响绑定。
