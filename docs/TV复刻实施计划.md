# TV 复刻实施计划与 Codex 执行时间估算

制定日期：2026-10-16；同日按用户要求修订为 Codex 执行口径。范围依据：[TV 原始需求与验收清单](TV原始需求与验收清单.md) 的 44 项要求及 11 条历史评审结论。

## 交付目标与边界

交易员在默认主页面选择候选、自选、持仓或已清仓标的，即可在同一套图表上核对证据、分析标绘、设置提醒、回放和复制快照；切股、切周期、关闭重开后继续原分析。界面、图标、配色、弹窗和操作逐项对照用户日常 TV 页面。

唯一暂缓项为分钟数据源及其依赖功能。其余要求没有从本次实施中删除。保留冻结策略、Store 写入边界、正式账本及原数据；无自动下单、外发消息或伪造分钟线。

现有原型与独立窗口作为可复用代码，不作为验收已通过的证明。当前未提交的主图嵌入、EMA 和 GAP 修改先审查、验证，再按下面的独立交付项整理，不能直接将混合工作树当成完整交付。

## 估算口径与可信程度

撤回原“65–105 人工工时／9–14 工作日”作为本项目交付周期的估算。它没有依据 Codex 实际执行速度，不能拿来推算本次完成日期，也不能简单除以某个 AI 提速倍数。

新版按当前一个 Codex 执行者顺序推进估算，不假定另有人或多个代理并行开发。利用已有图表、桥接及测试代码，估算还需进行的代码修改、命令／页面操作、测试、核验和常规返修；时间指这些工作累计的实际耗时，不再按人工每天 8 小时换算工作日。

估算为 **13–24 小时的活跃执行时间**，目标是全部非分钟要求完成实现和清单自验，形成可评审版本。它不表示用户最终验收已经通过；两位真人评审、用户试用、等待回复与会话中断不计入。当前尚未用第一阶段实测校准，置信度偏低，须保留区间，不作为固定截止时间。

估算理由：已有原型和独立窗口使很多功能可以修复、接入而不必重写；但默认主页面、非 GAP H2 证据、提醒管理等仍有实质缺口。11 种工具需要分别操作核验，DPI、剪贴板、保存关闭和并发无法仅靠快速生成代码验收。

## 顺序、执行时间与阶段出口

下面阶段按顺序推进；共用的保存、坐标、策略语义保护贯穿每阶段。真实 TV 核对也在对应工具与功能阶段继续进行，不能只在开始看一次页面。

| 阶段 | 实施内容 | 覆盖清单 | 估算 | 进入下一阶段前的证据 |
|---|---|---|---|---|
| 0. 建立对照与基线 | 复核当前工作树与差异清单；补查 TV 关键行为，安排后续逐项操作；优先验证嵌入容器风险 | W05/W07、N06/N07、D06–D09；44 项全量核对 | 0.5–1 小时 | 可复现的行为对照表；现有功能与缺口分开记录；无新增隐含排除项 |
| 1. 主工作区与 GAP 首批试用 | 主页面直接使用交互图表；候选、自选、持仓、清仓统一接入；单图默认与现有多图；DPI、尺寸、焦点、进程退出；切图前保存确认；完成 GAP 灰白样式并单独整理提交 | W01–W04、W06、S01/S02、S04/S05 | 1.5–3 小时 | 默认入口实机连续切股、切布局及重开；失败不丢分析；无巨大缩放、裁切或失去输入焦点；GAP 同样本对照，几何与价位不变 |
| 2. 各策略证据接入 | 逐策略保留原几何与标签，不把其他策略转成 GAP；策略卡与主图同步；候选历史／关注最新口径、持仓成本／买点／止盈止损；明确来源与复权坐标 | W04、S05–S08 | 1.5–3 小时 | 每类策略真实样本对照；周/月所属周期定位正确；证据只读且不覆盖人工对象 |
| 3. TV 图表与 11 工具 | 完成缩放、平移、轴拖动、框选、底部五键；收藏拖动；一次绘制退出；对象与端点移动；各工具专属弹窗、Fib 详细设置、色板、线宽、箭头透明度、磁吸、撤销、锁定、显隐和移除 | N01–N08、D01–D13、W05/W07 | 3–5 小时 | 每个工具完整执行“画→选→拖整体→拖端点→设属性→撤销/重做→重开”；真实 TV 对照与差异记录 |
| 4. 指标与分析功能 | EMA 真值与设置；日周月；提醒创建、编辑、启停、删除及前向触发；TV 日期选择／盲回放／退出恢复；当前视口 PNG 复制剪贴板 | F01–F08、S03 | 2–3 小时 | 数值对照、真实闭合行情提醒回归、回放未来数据隔离、Windows 剪贴板实际粘贴结果 |
| 5. 整体验收与交付 | 快速切股、改后立刻关闭、重启恢复、双窗口并发、后台提醒竞争；多 DPI；完整测试；文档、版本说明、PR 与演示证据 | S01–S03，全部 44 项及 11 条结论回归 | 1.5–3 小时 | 完整本地测试报告；真实数据和界面核验记录；逐项状态；可供两位真人 review 的 PR |

基础累计 **10–18 小时**，预留 **3–6 小时**用于嵌入、工具交互与策略证据核验中发现的常规返工，合计 **13–24 小时**。该区间不是已经测得的执行耗时；真正完成时按实际验证结果报告。

首个可试用主页面以阶段 0–1 为主，含局部返修目标为 **3–5 小时**：默认入口直接操作、GAP 中性样式、主要场景可选图并安全保存。此时工具细节和其他策略证据尚须后续阶段验收，不能称完整复刻。

## 第一处技术关口

当前嵌入实现已出现过 DPI 缩放／裁切问题，修正后未完成实机复核。优先验证：正常缩放、窗口缩放、输入焦点、坐标命中、快速切换与关闭握手。不能在这个基础不稳时继续叠加交互。

如果当前跨进程嵌入方式不能稳定通过上述动作，先调整图表容器实现，保留 Python 行情／Store 桥接和已有前端；不能以退回独立弹窗作为默认主工作区的交付。优先在最初约 1 小时的核验中明确主要风险。若证据表明必须更换容器方案，13–24 小时区间需重新评估，不能声称预留的 3–6 小时必然覆盖结构性改造；说明原因及阶段影响，不默默改交付范围。

## 其他主要进度风险

| 风险 | 处理与时间影响 |
|---|---|
| 工具设置存在“字段看得见但不生效” | 对照图元结果而非只看弹窗；尤其 Fib 各级、通道第三锚点、路径节点和仓位结构。常规返工计入预留工时。 |
| 非 GAP H2 策略证据尚未完整进入新主图 | 复用各策略既有语义，展示层适配，不动冻结算法；每类取得真实可追溯样本，不能用合成样本替代真实验收。缺样本时明确标记待真实数据验收。 |
| 保存、提醒和切周期互相影响 | 不改变 canonical 日期／价格、创建水位或原子 revision 保护；先加高价值回归，再接入口，避免重现 PR49 阻断项。 |
| 真实 TV 细节与当前推断不同 | 通过已授权的真实页面操作核对并更新行为记录；用户原图形保持完整；涉及用户记录的破坏性动作改在隔离样例验证。 |
| 评审或实际使用发现差异 | 修复后回归相关路径；跨阶段结构性问题重新估算，不能承诺用固定工时覆盖未知返工。 |

## 提交与验收安排

1. GAP 恢复作为独立提交／PR，不夹带图表重构；从当前混合改动中拆分相关文件与片段，不覆盖其他已有工作。
2. 后续按“主工作区与证据”“绘图交互与设置”“指标提醒回放快照及整体验收”组织可审查的提交；根据依赖关系组织 PR，注明依赖与各自验收状态。不能因前一个 PR 等评审而停止不冲突的开发，不自行合并。
3. 每个阶段在清单上附实现位置、测试与界面证据；只对验收通过的项目更新状态。发现其他非分钟差异继续列为本次待办。
4. 提交前执行 `.venv/Scripts/python.exe -m pytest -q` 完整检查，报告精确结果与对应版本；GitHub CI 单独记录。冻结清单逐字节不变，运行记录不入库。
5. 最终安排三层验收：代码测试、真实数据与界面操作、交易员连续实际使用。建议交易员使用 **1–3 个交易日**观察跨日恢复与提醒等行为；这是试用观察窗口，不保证足以覆盖所有长期行情边界。
6. 两位真人评审的等待时间与用户试用时间，不包含在 13–24 小时活跃执行时间内。最终合并与发布取决于既有 review 流程，不用 CI 通过替代人工批准。

## 估算更新方式

2026-10-17 进度校准：GAP 已独立提交 PR51；主页面嵌入、六策略证据适配、持仓／清仓接入、11 工具专属设置、提醒管理和按真实日线形成周／月回放已实现。原生多图往返／安全退出、提醒重启／启停已有证据；最新完整本地回归1209通过、166警告，前次两项失败已修复。剩余工作集中在逐工具鼠标动作、回放快照／多 DPI、真实并发及切股关闭边界和可评审提交。原 13–24 小时是实施前估算，已经不能当成从现在开始的剩余工时；当前按实际验收继续推进，不为符合旧估算省略需求。

最初约 1 小时核验后先校准一次；阶段 1 完成后按主工作区实际可用性更新；阶段 3 完成后按 11 工具逐项核验结果再更新。每次报告“已通过项目、剩余项目、预计剩余执行时间、影响估算的新证据”，不使用缺乏逐项证据的完成百分比。

本计划安排任务顺序，不创建后台任务或自动续跑机制。累计执行时间可以跨对话回合；不把未在执行的等待时间冒充开发时间，也不保证在用户离开后按某个钟点自动交付。
