# 行情恢复与数据源（2026-10-09）

## 使用方式

盘前“更新行情”左侧可选择 BaoStock 或 TickFlow。默认沿用 BaoStock；切换后手动更新，再扫描。选择会记住，但运行中的任务不能切换。失败不会偷偷换源，也不会把两个来源的价格接成一条历史。已有快照、扫描及研究报告保留原来源；日期候选列表可以查看旧成果，当前关注底图和新研究使用所选源。

TickFlow 首次建立自己的 2016 年起前复权日线，后续只补缺口；衔接价格变化时刷新该股票同源完整历史。每批最多 100 只、单连接、HTTP 请求间隔至少 1.5 秒，不在接口层重试。明确请求 `adjust=forward`，不把默认不复权价格当成前复权。成交量从接口“手”转成快照“股”。持仓图的不复权参照用 `adjust=none` 单独只读获取，不入行情仓或账本。

选择 TickFlow 不需要登录 BaoStock。但历史完整性必须使用已核验的交易日历：已有本地日历可按交易所公布的 2026 年休市安排向后延长；全新机器若没有 2016 年以来日历，会明确拒绝认证，不能从缺少 K 线猜休市。其他未公布年度也不猜。

## 连接和失败保护

BaoStock 板块同步改为一条子进程连接；查询有硬超时，停止可关闭子进程。OS 文件锁避免同一 Windows 用户的多个新版 Aplus 同时使用该供应商。连接前检查本机已有 10030 端口连接，发现 BPA 等工具正在使用时不新建连接。这不能阻止旧 BPA 在 Aplus 开始之后再启动，也不能协调其他电脑或共享出口 IP 上的客户端；请勿同时更新。

供应商错误保留来源、操作、原始错误码、耗时与消息到回执。登录或交易日历阶段失败也记录，不再用“行情不齐”覆盖最初原因。黑名单文字或错误码 `10001011` 立即停批；普通网络错误保留滚动五分钟失败计数，三次停止，缓存跳过不把失败计数清零。冷却写入现有 meta，重开程序仍有效；普通错误指数退避，黑名单本地至少等待六小时，实际解封由供应商决定。429 至少等一分钟，并尊重数字形式 Retry-After。并未证明此前限制访问的唯一原因，也不承诺改动后自动解封。

官方 [BaoStock 黑名单说明](https://www.baostock.com/blacklist) 不支持把旧配置注释“同 IP 五连接安全”当规则；冻结配置原文不改，运行路径不再使用并发连接。

## 缺口如何处理

不补造 K 线，不把所有缺口视为停牌。TickFlow 未提供整日停牌证据，因此逐日核对交易日历；只有已复核的公开公告区间可以解释缺少的日期。复牌当天不属于停牌区间；若停牌日反而返回成交 K 线，按证据冲突拒绝保存。证据原文链接记入任务回执。

证据目录不是全市场停牌服务。TickFlow 保存通过价格、日期、文件校验的真实 K 线，同时单独登记未知缺日，不再因为多年以前的未知缺口而丢弃整份行情。抓取覆盖只代表已请求并保存的范围，不代表每个历史交易日都有证明。首根 K 线之前仍不认证为停牌或 IPO 前日期。

日常扫描按原适配器实际使用的最近 300 根日／周 K 区间核验，仍至少需要 125 根已完成 K 线。区间内未知缺日、过期、文件缺失或损坏排除该股；日期与当前范围目录未核验时整批阻断。周线不要求尚未完成的当周数据。其余合格股票可扫描，但只要有排除项，任务明确标为“部分完成”，显示可扫描／应有及排除清单，不宣称全市场扫描完成。日／周分别检查，不放宽冻结策略；历史回测仍拒绝未认证历史缺口。BaoStock 原扫描完整性规则保持不变。

更新完成后，桌面显示黄色“完整性 / 补拉”入口，后台保存完整性回执和待查公告清单。默认只补拉影响当前扫描的缺口；可勾选包含扫描区间外历史缺口。已确认停牌及因上市历史过短而不足 125 根的股票不反复补拉。只请求指定股票，一次尝试后复检；仍有缺口提示查公告或稍后再试，不无限重试。失败保留旧快照，返回少于原有真实日期的刷新不能替换历史。Web 调试页也提供同一后台补拉入口。

公告核验是一次性维护的公开证据目录，记录停复牌日期、原文链接和证据版本；新增证据后在后台重新核验旧质量记录。缺口仍无法获证时进入回执中的待核验清单，不自动标成停牌。目前没有完成全部市场历史缺口的公告逐条核对。

## 来源隔离与协作边界

两来源各存一套价格快照与覆盖状态，但不复制账户账本或另建两套数据库。不可变行情 ID 包含来源／复权口径／内容，扫描和报告继续保留来源身份，禁止拼接跨来源价格。

BaoStock 继续使用原 `universe.csv`、`directories/`、`trading_calendar.json` 和 `sync_coverage`；TickFlow 使用 `sources/tickflow/` 的目录及日历，覆盖记录是 `sync_coverage:tickflow:<代码>`，质量记录绑定快照 ID，完整性回执与冷却也独立。首次升级只读兼容旧 TickFlow 的 `tradeStatus=unknown` 目录；不会借用 BaoStock 的当前目录认证 TickFlow。已核验历史交易日历及证券档案可作为公开证据只读复用，后续 TickFlow 更新写自己的文件，不修改 BaoStock 文件。

TickFlow 下载和补拉编排位于 `tickflow_service.py`，完整性回执位于 `tickflow_integrity.py`。共用 service/readiness/sync 仅保留必要路由和输入边界；本次不迭代 BaoStock 下载、连接、退避或并发设计，避免与伙伴的原路线排查互相覆盖。共用文件修改仍需双方 PR 评审，不能保证 Git 永远没有文本冲突。

## 持仓报价

新浪报价独立于盘前日线源。跨午夜、开盘前、午休和节假日保留最新有效报价，不再仅因“不是今天”丢弃昨天收盘；更近的已保存日线不能被旧报价覆盖。盘中供应商时间超过 45 秒视为滞后；失败保留旧价并在顶部解释 HTTP、解析或标的不支持等原因。

现价列只显示价格，不再附“复权历史收盘”等字样；来源、报价时间与失败原因在顶部。自动行情默认规则和隐私遮罩不变，报价只在内存，不写成交、资金流水、历史日线或正式盈亏日历。收盘价仍是供应商口径，不是交易所逐笔直连。
