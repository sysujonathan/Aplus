# 系统地图

## 工作流与边界

行情同步 / CSV → 校验 → 不可变行情快照 → 原策略适配层 → 扫描观察记录 → 人工计划。

同一份行情快照也可进入回测研究。研究输出只写研究报告，不写扫描观察或人工计划。策略工厂把新文件固定为版本，验证和研究后，人工启用才能进入日常扫描。

## 文件职责

| 文件 / 目录 | 负责什么 | 不负责什么 |
|---|---|---|
| app.py | 中文界面、收集用户选择、展示结果 | 不实现策略识别、不直接执行订单 |
| workbench/market.py | 股票代码、行情校验、数据源、行情版本、周线合成 | 不补造缺失价格、不打开旧库 |
| workbench/strategies.py | 冻结校验、调用原策略、提取结果、插件注册与启用 | 不修改原策略形态规则 |
| workbench/backtest.py | 逐期回放与明确的模拟成交假设 | 不宣称真实成交、不计算虚构组合净值 |
| workbench/service.py | 同步/扫描/回测/验证工作流、进度、停止与回执 | 不隐藏任务异常 |
| workbench/store.py | 唯一数据库结构管理者、事务、文件操作记录、人工计划历史 | 不读写原项目数据库 |
| core/strategies/ | 原有策略与内部依赖，12 个原文件 | 第一阶段禁止改动 |
| core/、config/ 其余冻结文件 | 原指标、评级、参数和兼容接口 | 不承接新产品的状态管理 |
| frozen_manifest.json | 冻结文件清单、来源提交、文件校验值 | 不能为绕过检查随意重新生成 |
| tests/ | 可重复验收案例 | 不使用真实工作记录 |

## 新版运行数据

所有新数据默认仅写 `runtime/`。开发和测试可用 `A_WORKBENCH_HOME` 指定另一个目录，测试始终隔离。

数据库中 datasets 是行情版本目录，observations 是策略原始观察，plans 是人工计划，plan_history 是人工修改历史，jobs/events 是回执，registry/validations 是策略工厂的版本与验证。研究逐笔结果单独保存，不冒充实际交易。

`market/` 的文件由数据内容、来源、复权和股票代码确定编号。workbench/sync.py 负责增量同步：先检查本地覆盖范围，已覆盖直接跳过，只补前后缺口；衔接处重取一根 K 线，价格或成交量变化时刷新该股票的完整范围。历史文件保留。sync_coverage 记录已保存快照及覆盖区间，数据库版本 2 从版本 1 自动添加此表，原有记录保留。旧版快照通过成功写入事件恢复已请求的历史起点。尚未返回的尾部日期不登记为已完成，防止供应商延迟被永久跳过。

使用单个后台任务执行器避免任务相互争用；1.0.1 的板块同步内部由 workbench/sync_batch.py 限制为两条独立子进程连接并行，各自复用会话且不共享供应商全局状态。界面可继续查看其他页面。不支持多个独立服务实例共用同一个运行目录。中断任务重启后标记为中断，不盲目续跑。

workbench/readiness.py 核对交易日历、股票目录与本地行情范围，扫描前发现缺失或过期则阻止整批计算。同步收尾保存 coverage 对账到任务回执，不把“处理完”当作“数据齐全”。具体判定边界见 1.0.1行情更新.md。

## 与旧系统的边界

策略计算及输入指标保留，旧扫描器、旧信号库、通知系统、回测器和 UI 不迁移。旧库未打开、未复制、未改结构。原项目的自动通知不属于本次用户定义的三个必要流程，第一版以本机界面和 CSV 导出交付。

旧系统作为策略计算对照，不把旧外围代码的错误作为兼容要求。日常扫描仍从原策略声明的活跃列取结果；统一回测则采用“首次观察、固定价格”的显式研究口径，两者不能混称完全一致的动态交易模拟。
