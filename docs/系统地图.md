# 系统地图

## 工作流与边界

1.1.0 日常入口为 `workbench/dashboard.py`：自动目录核验 → 增量同步 → 完整性保护 → 日线/周线策略匹配 → 看图/TradingView → 持续关注或人工计划。界面不再提供日常CSV导入入口。

数据库版本4新增 `watchlist`（股票代码、信号锚点、笔记、活动状态、加入及更新时间），由 Store 管理；只做加表迁移。关注是独立于 plans 的观察记录，不随扫描清空。信号锚点负责保存“为何关注”，关注图表通过股票代码读取最新 `baostock` 行情，因此行情前进不会丢失关注原因。旧市场页面与扫描页面合并为交易工作台。

行情同步 / CSV → 校验 → 不可变行情快照 → 原策略适配层 → 扫描观察记录 → 人工计划。

同一份行情快照也可进入回测研究。研究输出只写研究报告，不写扫描观察或人工计划。策略工厂把新文件固定为版本，验证和研究后，人工启用才能进入日常扫描。

## 文件职责

| 文件 / 目录 | 负责什么 | 不负责什么 |
|---|---|---|
| app.py | 中文界面、收集用户选择、展示结果 | 不实现策略识别、不直接执行订单 |
| workbench/market.py | 股票代码、行情校验、数据源、行情版本、周线合成 | 不补造缺失价格、不打开旧库 |
| workbench/strategies.py | 冻结校验、调用原策略、提取结果、插件注册与启用 | 不修改原策略形态规则 |
| workbench/h2_plan.py、prices.py | 原 H2 的次日 Entry／SL1、机会状态、风险与 MM R、集中 tick | 不改冻结形态识别、不管理实际成交 |
| gui/h2_chart.py | H2 历史结构与每日计划图、风险收益卡、K 线中心标注 | 不写数据库、不替用户确认交易 |

| gui/chart_renderer.py | 桌面与 Web 共用的纯图片绘制，按策略选择原标注或 H2 新计划 | 不加载 Tk、不写数据库 |
| gui/chart_annotations.py | 把冻结策略的专属标注接入桌面 K 线，统一坐标、信息框与深色外观 | 不重新定义信号、不改策略计算列 |
| workbench/backtest.py | 逐期回放与明确的模拟成交假设 | 不宣称真实成交、不计算虚构组合净值 |
| workbench/h2_replay.py、h2_replay_service.py | GAP H2 逐日机会／成交回放、统计、独立研究回执 | 不修改正式参数、不写观察或人工计划 |
| gui/afterhours.py、h2_replay_chart.py | 盘后结果、边界样本、当时可见的逐笔 K 线 | 不把触发当成交、不默认显示未来数据 |
| workbench/service.py | 同步/扫描/回测/验证工作流、进度、停止与回执 | 不隐藏任务异常 |
| workbench/store.py | 唯一数据库结构管理者、事务、文件操作记录、人工计划历史 | 不读写原项目数据库 |
| core/strategies/ | 原有策略与内部依赖，12 个原文件 | 第一阶段禁止改动 |
| core/、config/ 其余冻结文件 | 原指标、评级、参数和兼容接口 | 不承接新产品的状态管理 |
| frozen_manifest.json | 冻结文件清单、来源提交、文件校验值 | 不能为绕过检查随意重新生成 |
| tests/ | 可重复验收案例 | 不使用真实工作记录 |

## 新版运行数据

所有新数据只写本机数据仓。Windows 默认位置为 `%LOCALAPPDATA%\Aplus\runtime`，首次启动自动创建，不要求用户配置路径；切换分支、更新代码或重新拉取项目后仍关联同一份本地数据。旧版本若已在项目内留下 `runtime/workbench.sqlite3`，程序在新的默认仓尚未建立时继续沿用旧目录，避免升级后记录消失。`A_WORKBENCH_HOME` 仅作为显式覆盖入口，测试始终使用隔离目录。

数据库中 datasets 是行情版本目录，observations 是策略原始观察，plans 是人工计划，plan_history 是人工修改历史，jobs/events 是回执，registry/validations 是策略工厂的版本与验证。研究逐笔结果单独保存，不冒充实际交易。

桌面日期栏合并两类本地事实：`baostock` 行情快照的结束日，以及 observations 中已经保存的扫描日。启动默认选择最近扫描日，保证直接看到已有策略命中；同步只把最新行情日加入选项并提示待扫描，不改变当前选择。选中某日后再按来源优先级执行一次单来源候选查询，同日有正式 `baostock` 扫描时优先，否则可读取已迁入 Aplus 的 `legacy-engine-a` 历史成果，不会把两个来源混在同一候选集合。

桌面 K 线遵循三层绘图协议：公共层绘制蜡烛、成交量与 EMA；策略层调用该策略已有的 `annotate_chart()`，3K 由桌面适配层补齐两种明确信号；外观层只统一深色标签和配色。MTR、3K、GH1、GPb、GH2、AWIL 的几何线、缺口区、状态节点、入场/止损/目标等语义不能被通用星号替代。观察记录的 `asof/setup_date` 是历史标注锚点；早期迁入记录即使 payload 缺少日期，也从 observations 的正式字段补齐，不改写数据库。

`market/` 的文件由数据内容、来源、复权和股票代码确定编号。空仓第一次点击更新行情，或检测到旧数据尚未覆盖到 2016 年时，自动补齐完整历史；完整覆盖建立后，workbench/sync.py 先检查本地范围，已覆盖直接跳过，只补前后缺口。衔接处重取一根 K 线，价格或成交量变化时刷新该股票的完整范围。历史文件保留。sync_coverage 记录已保存快照及覆盖区间，数据库版本 2 从版本 1 自动添加此表，原有记录保留。旧版快照通过成功写入事件恢复已请求的历史起点。尚未返回的尾部日期不登记为已完成，防止供应商延迟被永久跳过。

使用单个后台任务执行器避免任务相互争用；1.0.1 的板块同步内部由 workbench/sync_batch.py 限制为两条独立子进程连接并行，各自复用会话且不共享供应商全局状态。界面可继续查看其他页面。不支持多个独立服务实例共用同一个运行目录。中断任务重启后标记为中断，不盲目续跑。

workbench/readiness.py 核对交易日历、股票目录与本地行情范围，扫描前发现缺失或过期则阻止整批计算。同步收尾保存 coverage 对账到任务回执，不把“处理完”当作“数据齐全”。具体判定边界见 1.0.1行情更新.md。

## 与旧系统的边界

策略计算及输入指标保留，旧扫描器、旧信号库、通知系统、回测器和 UI 不迁移。旧库未打开、未复制、未改结构。原项目的自动通知不属于本次用户定义的三个必要流程，第一版以本机界面和 CSV 导出交付。

旧系统作为策略计算对照，不把旧外围代码的错误作为兼容要求。一般日常扫描从原策略声明的活跃列取结果；GAP H2 在冻结原形态之上用独立计划层生成 High + tick、回调 Low - tick 和 MM 的待挂提醒。统一回测继续采用冻结输出的“首次观察、固定价格”口径，显式关闭计划价转换；两者不能混称完全一致的动态交易模拟。
