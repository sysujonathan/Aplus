# 系统地图

## 工作流与边界

1.1.0 日常入口为 `workbench/dashboard.py`：自动目录核验 → 增量同步 → 完整性保护 → 日线/周线策略匹配 → 看图/TradingView → 持续关注或人工计划。界面不再提供日常CSV导入入口。

数据库版本4新增 `watchlist`。版本5新增原始人工成交账本；版本6增加两种建账方式以及 `positions`、`position_fills`、`closed_trades`；版本7新增 `cash_flows`，记录利息、分红、红利税、转入转出与其他非交易收支；版本8为账户增加可选资金账号字段，用于本地脱敏展示。升级只加表/字段，不删除旧记录。关注是独立于 plans 的观察记录，不随扫描清空。信号锚点负责保存“为何关注”，关注图表通过股票代码读取最新 `baostock` 行情，因此行情前进不会丢失关注原因。

行情同步 / CSV → 校验 → 不可变行情快照 → 原策略适配层 → 扫描观察记录 → 人工计划。

同一份行情快照也可进入回测研究。研究输出只写研究报告，不写扫描观察或人工计划。策略工厂把新文件固定为版本，验证和研究后，人工启用才能进入日常扫描。

## 新版运行数据

所有新数据只写本机数据仓。Windows 默认位置为 `%LOCALAPPDATA%\Aplus\runtime`，首次启动自动创建，不要求用户配置路径；切换分支、更新代码或重新拉取项目后仍关联同一份本地数据。旧版本若已在项目内留下 `runtime/workbench.sqlite3`，程序在新的默认仓尚未建立时继续沿用旧目录，避免升级后记录消失。`A_WORKBENCH_HOME` 仅作为显式覆盖入口，测试始终使用隔离目录。

数据库中 datasets 是行情版本目录，observations 是策略原始观察，plans 是人工计划，plan_history 是人工修改历史，accounts 是建账方式与风险规则，positions 是持仓及止盈止损计划，position_fills 是分批买卖及费用，closed_trades 是自动归档或手工补录的清仓摘要，cash_flows 是不属于买卖成交的资金调整。旧 executions 保留兼容，不作为新版页面的唯一入口。jobs/events 是回执，registry/validations 是策略工厂版本与验证。研究逐笔结果单独保存，不冒充实际交易。

盈亏日历为独立的账户日收益事实，通过 Store 存在 meta 的 `daily_returns:<账户ID>` 中，仍兼容结构版本 8。按日期保存券商记录或本地计算，券商记录优先；同一日期重复刷新不叠加。这里的金额不写入清仓盈亏或资金调整，不改变资产。完整成交可按历史快照逐日估算；手工清仓摘要缺股数和成交价，覆盖到最后一笔摘要的历史日期不推算账户整体日收益。前复权价格跨企业行动无法完全对齐交割口径，需用券商记录核验。

持仓即时行情仅保存在桌面内存，由单后台线程取价和 Tk 定时回调显示；关闭开关、切换账户或销毁窗口使旧请求结果失效。Store 的 meta 保存 `holding_auto_quotes` 开关及 `holding_cash_reference:<账户ID>` 快照现金基准（现金、已投资净额、资金调整），不改变 schema 8。重新确认账户设置在同一事务内替换基准；历史建账按初始资金、清仓及剩余净投资计算现金，快照建账按基准加真实账本变动计算现金。公共绘图器的持仓水平线参数默认为空，研究图的默认输出不变。

桌面日期栏合并两类本地事实：`baostock` 行情快照的结束日，以及 observations 中已经保存的扫描日。启动默认选择最近扫描日，保证直接看到已有策略命中；同步只把最新行情日加入选项并提示待扫描，不改变当前选择。选中某日后再按来源优先级执行一次单来源候选查询，同日有正式 `baostock` 扫描时优先，否则可读取已迁入 Aplus 的 `legacy-engine-a` 历史成果，不会把两个来源混在同一候选集合。

桌面 K 线遵循三层绘图协议：公共层绘制蜡烛、成交量与 EMA；策略层调用该策略已有的 `annotate_chart()`，3K 由桌面适配层补齐两种明确信号；外观层只统一深色标签和配色。MTR、3K、GH1、GPb、GH2、AWIL 的几何线、缺口区、状态节点、入场/止损/目标等语义不能被通用星号替代。观察记录的 `asof/setup_date` 是历史标注锚点；早期迁入记录即使 payload 缺少日期，也从 observations 的正式字段补齐，不改写数据库。

历史缺口关注若当前重算缺少原形态的精确列，GUI 仅在真实突破窗口同时印证归档 Floor 与 MM 时恢复标注副本。不能用较新突破、估算低点或窗口内另一笔信号代替原结构；证据不足或原信号在可见窗口外时显示“结构待核对”，只保留归档计划价。策略标注与底图共用同一可见日期窗口，缩放和向前翻图时坐标一致。

`market/` 的文件由数据内容、来源、复权和股票代码确定编号。空仓第一次点击更新行情，或检测到旧数据尚未覆盖到 2016 年时，自动补齐完整历史；完整覆盖建立后，workbench/sync.py 先检查本地范围，已覆盖时核验登记的 SHA-256 后直接跳过，不再重复解析未变化 CSV，只补前后缺口。衔接处重取一根 K 线，价格或成交量变化时刷新该股票的完整范围。历史文件保留。sync_coverage 记录已保存快照及覆盖区间，数据库版本 2 从版本 1 自动添加此表，原有记录保留。旧版快照通过成功写入事件恢复已请求的历史起点。尚未返回的尾部日期不登记为已完成，防止供应商延迟被永久跳过。

使用单个后台任务执行器避免任务相互争用；2026-10-09 起 BaoStock 板块同步改为一条独立子进程连接，OS 锁、本机已有连接检查、持久冷却与结构化错误由 workbench/provider_guard.py 管理。TickFlow 复用可终止子进程机制但不访问 BaoStock，每批最多 100 只。界面可继续查看其他页面。不支持多个独立服务实例共用同一个运行目录。中断任务重启后标记为中断，不盲目续跑。

workbench/sources.py 管理当前日线来源及分来源覆盖；BaoStock 沿用 sync_coverage，TickFlow 使用现有 meta 的 sync_coverage:tickflow:<代码>，schema 8 不变。workbench/tickflow.py 显式取前复权完整历史，不能拼接 BaoStock 尾部；来源切换不改旧快照或报告。workbench/suspensions.py 是有限的公开停牌公告证据目录，不是全市场停牌识别服务，未知缺口仍拦截。上述最新路由替代本页早期固定 baostock 的读取说明；日期候选保留旧来源，但一个候选集合仍只取一个来源。详见 [行情恢复与数据源](行情恢复与数据源.md)。

workbench/readiness.py 核对交易日历、股票目录与本地行情范围，扫描前发现缺失或过期则阻止整批计算。同步收尾保存 coverage 对账到任务回执，不把“处理完”当作“数据齐全”。具体判定边界见 1.0.1行情更新.md。

日常扫描按股票加载和截断行情，每只股票只生成一次公共指标帧，再把独立副本交给各冻结策略。该股票的缓存查询、扫描缓存、命中记录、审计事件和进度更新按一次事务提交；SQLite 仍由主服务线程写入，不让计算并发写库。扫描缓存版本只由计算语义、计划价层和冻结清单决定，不受界面进度文案影响。

## 与旧系统的边界

策略计算及输入指标保留，旧扫描器、旧信号库、通知系统、回测器和 UI 不迁移。旧库未打开、未复制、未改结构。原项目的自动通知不属于本次用户定义的三个必要流程，第一版以本机界面和 CSV 导出交付。

旧系统作为策略计算对照，不把旧外围代码的错误作为兼容要求。一般日常扫描从原策略声明的活跃列取结果；GAP H2 在冻结原形态之上用独立计划层生成 High + tick、回调 Low - tick 和 MM 的待挂提醒。统一回测继续采用冻结输出的“首次观察、固定价格”口径，显式关闭计划价转换；两者不能混称完全一致的动态交易模拟。
