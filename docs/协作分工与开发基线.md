## 开发与备份

GitHub main 是共同代码来源。各自从更新后的 main 创建功能分支，完整测试通过后经 PR 合并；不强推 main。

各自的 Google Drive 用于备份，不用于互相覆盖工作目录。每次备份应附备份时间、分支、完整提交号及是否存在未提交改动；未提交内容需要单独保留差异或文件，提交号本身无法恢复它们。

代码备份与个人运行数据分别管理。runtime/、密钥、持仓等不提交 Git；备份运行数据库前停止写入，或使用一致性备份方式。虚拟环境可按锁定依赖重建。本次接入不设置自动备份，也不覆盖既有核心副本。

每位协作者首次启动时都会自动获得当前 Windows 用户专属的固定本地数据仓，无需创建目录、设置环境变量或手工维护数据库。首次更新建立完整历史，此后同一个“更新行情”操作只补本地缺口。GitHub 的 clone、pull 和分支切换不会改变本地数据仓，也不会把本地数据提交到仓库；`A_WORKBENCH_HOME` 只用于显式迁移和测试隔离。
