# 老版本一次性安全过渡

适用于仍在使用旧更新器、软件内被公开测试证书误拦截的 Windows x64 / Python 3.12 安装。此工具发布并经官方 main 验收后使用；它不能安装尚未合并的 PR。

1. 从系统托盘完整退出 Aplus，也退出共享同一安装和数据的 Web 服务。
2. 解压官方安全过渡工具包，双击其中的 `安全过渡更新.vbs`。
3. 选择原来的日用安装目录，例如 `Aplus_daily`。不选择数据目录，不搬运代码、Python 或数据库。
4. 助手接手后等待结果。需要的依赖会安装到独立环境，完成后自动打开软件；失败会保留旧环境及恢复材料。
5. 本次过渡完成后，以后从软件内点击“更新并重启”。日常仍使用原来的 VBS 入口。

不要直接把过渡脚本复制进旧仓库：新增未跟踪代码会被开发工作区保护阻断。工具包从解压位置运行即可。

助手自动沿用启动器配置的 `A_WORKBENCH_HOME` 和既有默认数据路径规则，不创建空账户代替旧数据。安装目录存在未提交修改、任务仍运行、事务日志未清理或版本尚未发布时会停止；不会强制关闭进程或丢弃修改。

过渡入口只从 `sysujonathan/Aplus` 获取精确 main，并检查该提交最新 `A acceptance` 成功。它在临时目录提取官方代码，调用原有维护更新器；准备期间 main 变化则停止重试，不把旧检查结果用于新提交。实际代码替换、备份、回退、启动回执和环境指针仍由原更新事务管理。

本次补齐的逐包哈希锁不改变现有依赖版本。老安装缺少正式锁内组件时，新环境自动安装完整锁定版本并核对安装包 SHA-256、`pip check` 和原生启动。原 `.venv` 保留；下载或安装失败不会启用半成品。

公开测试证书只按精确路径和审阅过的 SHA-256 放行；其他 PEM、私钥、用户证书、凭据和业务数据库继续受保护。VBS 的中文提示使用 Unicode 常量，避免系统代码页导致启动脚本语法错误。

技术回执和安装失败日志位于原安装 `.git/aplus-update/`。普通用户只需查看更新助手的结论；不要删除锁、运行目录或备份来重试。

修复 PR 合并前，仅完成隔离候选版本演练；实际日用安装的升级须在人工批准、main 发布验收后再执行。本工具没有增加跨 Python 版本自动安装或独立原生更新监督器。
