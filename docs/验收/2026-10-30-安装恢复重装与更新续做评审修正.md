- **P1 属实。** 已接续数据每次启动都会被残留事务日志挡住。现区分首次只读识别与已绑定数据的明确恢复确认：
  先在程序/Web 已退出条件下保存数据库、journal/WAL/SHM 的原字节快照并核对，再让 SQLite 自行恢复、
  做完整性检查；其他连接占用、空间不足或备份变化时停止。不手动删事务文件，不创建替代空库或更改 schema。
- **卸载重装问题属实。** 卸载精确删除程序生成的 current/previous 指针及临时指针，未知文件/数据保留。
  安装检查遍历目标子目录，数据库及目录联接均停止，不用清空文件夹解决重装。
- **双实现确有漂移风险，但原生测试并非零覆盖。** 原先已有真实 C# 编译与运行测试。
  此轮删除未被生产调用的 Python 恢复实现及入口，保留原生这一套；原来的模拟测试转为实际运行发货启动器。
  同时对齐完整离线 manifest、日期、序号、阶段及旧指针验证。
- **截图是实际兼容问题。** .NET 的 EnvironmentVariables getter 无法容纳仅大小写不同的代理键。
  启动器现不构造该不区分大小写字典，仅设置自身进程的安装根变量并继承原生环境块。
  真实启动器使用同时包含 HTTPS_PROXY/https_proxy 的测试环境启动子程序，未读取或输出用户代理凭据。
- **没有复现现有 sequence 被强转 Int32 的溢出。** 旧代码 Int32 用于 schema/PID，不能把“未来可能误用”
  当成现有致命 bug。版本格式不一致属实，现两端对齐日期及当日序号，并用 Int64 验证 12 位 sequence。
- **空间与下载重复问题属实。** 确认真正启动成功后清理已验证下载包；保留当前/上一版本，只清理带构建归属清单、
  集合及哈希一致、没有活跃进程和未知内容的更早版本。旧试用包没有清单时保留；数据库和用户备份不在清理范围。
  编辑/图表保存拦截后重查官方发布并复用已校验包；网络失败清除过期可更新状态，回“检查更新”。
  下载前检查空间，临时文件独立命名。安装目录禁止生成新的 pyc，确保归属清单可持续核对。
- 清理失败只记录 deferred，不回滚已成功启动的版本；不递归强删未知内容。
- 删除无生产调用的 require_signature、APLUS_INSTALLED；当前身份读取异常也进入检查结果，不让按钮卡住。
- 发布列表改为分页读取；保留 contents:read，不为草稿可见性扩大权限。重复发布仍拒绝覆盖。
  快捷方式扫描保持过滤后取首30个匹配项和后台超时；放到过滤前会漏掉排在后面的 Aplus，故不照改。
