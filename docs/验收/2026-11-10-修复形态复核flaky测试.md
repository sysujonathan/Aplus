## 问题

main 全量验收（PR #123 合并后，run 42746239813）1 failed / 2578 passed，失败用例为
`tests/test_shape_review115.py::test_skipped_templates_are_visible_from_result_history`，
并连带 Windows installed release 的「Admit exact accepted main」失败、无新发布。

## 根因（独立调查，证据见 Issue）

测试缺陷，非功能回归，与 PR #121/#123 无关：

1. 断言永假：用例断言状态文本包含子串「未运行模板 1」，但任务完成消息走长文案分支，
   实际语序为「1个模板未运行」（workbench/shape_tasks.py 的 skipped_summary），永不匹配。
2. 时序竞态：dialog.status 有两个写入者，_poll()（每 400ms）会用任务 message 覆盖
   _display_run() 写入的状态行；测试忙等不泵事件，读到哪套文案取决于时序，故偶发红绿。
3. 该用例与两套文案同在提交 bfe5ccb（随 PR #115 合入）诞生，不一致从第一天即存在；
   此后 main 全量曾三绿一红，与竞态机理吻合。

## 修复

断言改为直接针对 wait_for_shape() 返回的任务状态 message（不受 Tk 轮询覆盖影响）：

- 删除：`assert '未运行模板 1' in dialog.status.get()`
- 新增：`assert '没有兼容的跟踪模板' in status['message']`
- 新增：`assert '1个模板未运行' in status['message']`

用例其余断言（按钮 state、弹窗内容、_resume 一致性）保持不变。由 Codex 落盘（Lord 派活并验收 diff），产品代码未改动。
