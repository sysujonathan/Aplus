## 实现

- 构建任务只有读取权限。仅接受官方 main push 的成功 A acceptance；CLI 入口再次核对完整 SHA、工作流路径、最新运行/attempt、分支和仓库，已发布同一提交则跳过。
- 沿用干净官方构建、无控制台行情 IPC、冻结实际加载器及真实 GUI/WebView 冒烟，失败不向后发布。
- 发布任务单独取得 contents:write，只读取同一构建任务返回的 artifact ID；清单提交必须等于构建提交，使用 GitHub 内置短期令牌。
- 草稿先上传，再下载清单与 Setup 校验真实字节；公开前重查最新 main、精确 push CI 和版本顺序。主线前进、错误字节、未知标签或更高稳定版均停止。
- 中断后只补传同一草稿缺失的文件，不覆盖资产；已公开同一包重试不重复发布。公开后执行客户端 load_manifest 并保存 published 回执。

GitHub 官方说明：[`workflow_run` 权限边界](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)、[任务级权限](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)。
本轮未改变 checks.yml、必需检查名称、完整 pytest 命令、PR/main 触发或分支保护。
