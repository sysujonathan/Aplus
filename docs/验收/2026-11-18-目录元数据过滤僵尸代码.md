# 2026-11-18 目录元数据过滤僵尸代码

Issue #158 的①-a，R2。盘前按板块更新时，目录先排除名称含「退」或总股本为 0 的代码，后续批拉和扫描使用缩小后的范围。同步回执的 `excluded_by_metadata` 与 `excluded_retired` 分别列代码。两条规则都命中时档案优先，回执只记一次。冻结策略、历史行情、停牌证据、行情缺口规则与同步中止口径沿用原实现。 [Issue #158](https://github.com/sysujonathan/Aplus/issues/158)

## 改动与人工复核

- TickFlow 的目录帧保留 `total_shares` 和 `float_shares`。规则对当前目录使用 Pandas 向量化匹配，未知股本继续留在目录。每市场仍只发一次目录请求。
- 旧目录缩减检查接受本次明确排除的代码，其他缺员仍走原保护。腾讯共用该过滤，缺少股本列时仍能按名称筛查。若已过滤的 TickFlow 目录缺少原有腾讯成员，腾讯改用其他合格目录或自身公共目录核验。
- 复核时从回执找到代码，核对证券交易所公告与供应商元数据。确认误伤后，在 `workbench/readiness.py` 的 `DIRECTORY_METADATA_ALLOWLIST` 中按 `frozenset({'<市场前缀>.<六位代码>'})` 的形式加入复核通过的代码。下一次完整目录更新生效，档案已确认退市的代码仍排除。交付时白名单为空。
- 为控制加列和匹配成本，将板块识别的原正则合为一条预编译匹配。对沪、深、北各 100 万个六位代码及 7 个边界输入与基线逐一比对，结果一致。
