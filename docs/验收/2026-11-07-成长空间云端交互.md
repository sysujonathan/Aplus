# 成长空间云端操作与交互定向记录

基线：main `a02cb8e`。风险 R2，共享写入与界面并发。目标是发布、下架时仍可研究其他案例，减少重复网络往返；不改 OAuth、Drive 目录/权限协议、个人记录、数据库结构、冻结策略、交易账本、CI 分级或安装更新门禁。

## 实际改动

- `workbench/pa_shared.py`：固定阶段耗时；小文件 multipart、大文件保留原 resumable；预分配 ID、持久保留记录、存在性检查、逐字节回读均保留。省去 manifest 的重复正文下载，最终元数据继续核验目录/贡献者，并比较刚验证字节的 MD5，防止期间被改写。
- 发布后仅把已确认原件纳入现有有效缓存，不凭上传回执建立/恢复访问授权，不再附加全库 refresh 与 bootstrap。
- 上下架前后仍联网核验当前身份、文件夹权限、原件 MD5/目录/贡献者、最新协作头及本次写入是否可见；从两次全库刷新改为两次目标同步。复用通过当前目录/所有者验证的未变化协作缓存。原始文件、修订与留言不改写、不删除。
- `gui/growth_bridge.py`：复用 WebView 的请求线程，仅序列化云端写入；不持有普通浏览锁等待上传。按案例防重，同案修改及同窗口切换/断开账号须等待；跨窗口账号代次与权限 epoch 仍校验。全库刷新提交加目录代次检查，防止迟到快照覆盖目标写入。
- 前端只维护本窗口进行中的调用与少量完成提示，无任务服务/轮询器。发布一次确认，完成后轻提示与查看公共版本入口；下架一次确认，完成提示可恢复。迟到回执只更新相同案例和相关统计，保留另一案例的编辑框、版本、页面、筛选及草稿。查看公共结果后返回原研究和原图缩放。
- 正常退出继续沿用关闭确认保护，额外等待后端云端调用（即使旧页面已丢弃响应）；超时不销毁窗口，不询问放弃已在提交的资料。

## 小样本阶段测量

**以下是本机隔离 HTTP 仿真的实测值，不是 Google 实网性能或正式环境承诺。** 使用一个单图、一个双图 PNG 案例，逐 HTTP 请求固定增加 5ms；本地 Store 位于 `.test-pa-growth/`，没有打开正式数据库或上传真实公共库。基线在优化前加入相同计时后记录；不做大规模基准，不据单次墙钟值承诺加速倍数。阶段存在嵌套，不能直接相加。

| 操作 | 总耗时 ms：前 → 后 | HTTP 请求：前 → 后 | 上传阶段 ms：前 → 后 | 精确回读 ms：前 → 后 | 目录同步 ms：前 → 后 |
| --- | --- | --- | --- | --- | --- |
| 单图发布 | 239.77 → 132.58 | 27 → 16 | 32.62 → 22.10 | 33.78 → 34.04 | 全库 48.41 → 无附加全库刷新 |
| 双图发布 | 318.96 → 158.12 | 32 → 20 | 46.65 → 28.00 | 46.59 → 44.54 | 全库 49.61 → 无附加全库刷新 |
| 下架单图案例 | 147.53 → 124.06 | 16 → 14 | 11.10 → 7.31 | 11.00 → 11.07 | 全库合计 83.45 → 目标合计 70.88 |
| 下架双图案例 | 173.64 → 118.78 | 16 → 14 | 10.94 → 7.39 | 11.17 → 11.45 | 全库合计 90.36 → 目标合计 68.35 |

上传前存在性检查：单图 16.58 → 16.64ms、双图 25.10 → 21.58ms；下架 5.56/6.05 → 5.62/5.49ms。最终发布确认：单图 17.94 → 5.84ms、双图 17.91 → 9.66ms。优化后的桥接结果摘要仅用本地有效目录，单图/双图分别 2.03/2.20ms。没有通过取消回读或放宽权限校验缩短等待。

生产 JS 在 Node VM 中、每次桥接调用固定延迟 5ms：发布从 `publish_case → refresh_shared → bootstrap` 变为单次 `publish_case`，下架从 `set_public_visibility → bootstrap` 变为单次 `set_public_visibility`。样本等待总计发布 42.94 → 5.78ms、下架 29.24 → 9.02ms；HTML 生成分别 4.28 → 4.39ms、0.13 → 0.05ms。**这不是 Windows WebView 的绘制耗时**。新增 `cloud_wait` / `ui_update` 可记录真实运行中的桥接等待与更新代码耗时；本轮未进行 Windows 多轮自动化或原生绘制测量。

Google 的 multipart 用法依据：[上传指南](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[预分配文件 ID](https://developers.google.com/workspace/drive/api/guides/create-file)。客户端仍按原协议逐文件核对，未引入并发上传线程。

最后补上最终元数据被改写的拒绝边界及查看结果后的研究/原图返回，仅重测对应两组 **3 passed，1.85s**，不重复其余已经通过的用例。生产 JS `--cloud-operations` 覆盖跨案例迟到回执、同案防重、切页、未修改直接关、有修改确认、返回缩放、账号失效丢弃旧响应；`--quick-actions` 通过，覆盖三个快捷入口及发布反馈。`node --check` 与 `git diff --check` 通过。

目标同步最终采用与全库刷新相同的目录代次保护：若读取期间另一操作已经更新本地目录，报错且保留新快照，不将旧协作缓存混入刚读取的目标记录。追加该反向边界后，仅重测对应并发/撤权用例 **1 passed，0.70s**。以上是 8 项唯一 pytest 用例及受影响用例的局部重测，并非累计扩大验证范围。

## 边界与未完成验证

- 没有跨重启常驻服务。普通关闭等待；强杀进程可能留下待确认上传，按既有 ID 重试，不伪报成功。
- 历史协作记录没有可按案例检索的属性，目标同步仍列举协作元数据，不是 O(1)；同窗口云端写入继续串行，其他案例浏览可以并行。
- Drive 权限、元数据和目录可见性不是原子事务；保留并发冲突/确认不足报错，不承诺强一致性。编辑者仍可绕过 Aplus 改删 Drive 文件。
- 尚未验证 Google 实网阶段耗时及 Windows 实际操作手感；仿真测量、代码回归不能替代这些证据。本轮未重跑 OAuth、全仓/完整 PA、安装升级、行情/策略/账本测试，没有改 CI 或正式发布门禁。
- Codex 交付以 PR 为准；GitHub 必需 CI 和人工评审仍须在合并前完成，本地通过不代表已满足合并条件或已发布给用户。
