# TickFlow 扫描作业内并行验收

## 范围与基线

基线：GitHub main `773b24481db0d881003acc77aa6706488158d21a`。用户明确本轮以 TickFlow 主力源的盘前体验为目标，评估附件后实现并提交新 PR；BaoStock 保留替补流程。本次是扫描执行模型和安装私有入口变更，按 R3 验证。

本 PR 先实现收益最有依据的一项：大批量 TickFlow 冷判断扫描的有界进程计算。它没有改变更新阶段的网络、CSV 快照保存或完整性收尾，不能承诺完整“一键盘前”从 22 分钟降到 2 分钟。冻结 core/config/manifest、原有策略适配层、Store/schema、行情供应商、账户和交易写入边界均不修改。

## 对附件建议的判断

- 采纳“CPU 密集的逐股计算优先进程并行”和“主进程按原顺序逐股耐久提交”。公开可见的 TSP 代码同样支持列式数据、共享矩阵和计算缓存；其外层策略 worker 默认 1，不把它理解为盲目增加线程即可提速。
- 附件 22 分钟任务与逐段基准是定位线索，不能把扫描阶段总时长都认定为 detector CPU。提供的 `bench2.py` 从整个 market 目录随机取历史快照，`tail(1095)` 也不保证原文件有 1095 根；不能据此认定都是“最新 TickFlow、相同长度、正式可扫池”。本轮另用 SQLite 只读快照筛选最新 TickFlow，同日等距抽样，逐文件校验原 SHA 后复制，不重写或补造行情。
- 不采用删减 `assert_frame_equal`、抽样代替每次结果约束、缩小股票池或取消 SHA。也不直接沿用昨日 EMA 状态：原语义先取最近 300 根再初始化 EMA，滑动窗口起点变化需要单独证明等价。
- 每日 Parquet、复权因子分层、面板公共指标和面板必要条件是后续独立方案，涉及数据版本与数值边界；本 PR 不混入存储迁移、WAL、事件合并或新的 H2 门禁。
- 不把“默认 OFF + SHADOW 前置”当作当前唯一政策。2026-10-27 稳定快速版已有明确本机授权机制；本次不自动创建或续签授权。有实际生效的快拒控制器时继续原路径，避免新进程计算破坏其抽查、缓存或熔断状态。
- 用户在本轮补充：刚休市，服务器行情可能未完整或稳定。因此现有真实快照计时仅供参考，既不认证供应商完整性，也不代替稳定时段正式安装的全市场盘前验收。

TSP 对照固定到 `6dd370584b2405490de84fd6f70f170f1992fb63`：[默认并发配置](https://github.com/shy3130/tick-stock-panel/blob/6dd370584b2405490de84fd6f70f170f1992fb63/backend/app/config.py)、[共享策略矩阵](https://github.com/shy3130/tick-stock-panel/blob/6dd370584b2405490de84fd6f70f170f1992fb63/backend/app/strategy/engine.py)、[全市场历史预热缓存](https://github.com/shy3130/tick-stock-panel/blob/6dd370584b2405490de84fd6f70f170f1992fb63/backend/app/tickflow/repository.py)。没有把其缓存命中或渐进返回时间当作相同 PA 策略的完整计算基准。

## 实现与不变契约

`scan_parallel.py` 负责资源上限、有限预取、隐藏进程及异常回退；`scan_worker.py` 不创建 Store，只读同源不可变快照并调用原 `prepare/prepare_indicators/signal_at_end`。主服务仍重新读取、验证 SHA，按原股票/策略顺序提交缓存、命中、错误、审计和有界回执，保留现有机会身份与计算版本。

最多 8 个计算进程，受半数逻辑 CPU 与可用内存预算限制；不足 64 只待计算股票保持串行。研究插件、非 TickFlow、非默认原生参数及生效快拒控制器保持原路径。`APLUS_TICKFLOW_SCAN_WORKERS=1` 可回退，默认 auto，非法设置串行。任务停止终止本轮子进程，尚未提交的预取结果丢弃；计算进程异常关闭池并从当前股票继续原串行路径。业务异常保留原股票/策略位置。

安装 EXE 新增私有 `--scan-worker` 分派，先安装原冻结源码加载器，再恢复私有管道，不进入桌面或首次引导。协议采用 ASCII JSON 转义传输 Unicode，避免 windowed EXE 保留 Windows 系统编码时损坏中文路径、H2 payload 和错误文本。正式构建增加 `tools/test_installed_scan.py` 离线检查。

实现沿用项目已有的私有进程／管道入口方式，而非让 frozen EXE 隐式重入普通桌面入口；同时可以在 Python 3.12 中直接终止本任务失联或停止的子进程，不依赖进程池私有属性。父进程的线程只等待管道，实际指标与检测器在独立 Python 进程中执行。

## 代码与原生验证

本机环境：Windows 11，Python 3.12.13 / NumPy 2.5.3 / pandas 2.3.3，20 个逻辑 CPU。所有代码测试和 EXE 探针使用工作区内一次性 Store，不安装或重启日用工具。

新专项包括：六检测器真实子进程对拍、含真实检测器命中的 H2 完整待挂 payload、周线、部分/完整缓存、重复 dataset、原股票/策略审计顺序、损坏快照与预取后篡改、业务异常、真实子进程退出/回退、有界任务、阻塞取消/恢复、事务前/中/后 `os._exit(77)` 崩溃恢复，以及 source/frozen 分派。

扫描/盘前/五门禁相关组合：262 passed，11 条既有 pandas/NumPy 弃用提醒，229.50 秒。最终新专项：23 passed，1 条既有提醒，39.08 秒，另含两只 H2 正命中进入主服务后的机会 ID、价格、payload 与去重对照。

最终完整回归：**2364 passed，0 failures / errors / skipped，2032.47 秒**。268 条提醒包含 pandas/NumPy 弃用和 JUnit `record_property` 兼容提示。命令：`python -B -m pytest -q --basetemp=.test-parallel-full-logged -p no:cacheprovider --tb=short --junitxml=.test-parallel-full-result.xml`。完整 XML 已移入本机隔离目录 `.test-parallel-validation/full-result.xml`，聚合统计见 [回归证据](evidence/tickflow-parallel-regression.json)。第一轮长终端回归仅观察到 94% 进度、未取得终态，不计入通过；因此追加本轮带日志/XML的完整运行，不能用进度替代结果。

用生产 `packaging/Aplus.spec` 构建 preview windowed EXE，冻结源码保持原字节。真实 EXE 探针证明：中文路径、真实 H2 待挂结果、中文错误、两个并发 EXE 进程、源 SQLite 字节不变、退出后无存活子进程。既有三源 provider 离线 IPC/停止/未知参数探针通过；没有向供应商发请求，没有打开正式桌面。未构建或安装正式 Setup，预览 EXE 不能冒充正式发布。

EXE 核心模块与最终工作区文件 SHA-256 一致，证明见 [离线 EXE 证据](evidence/tickflow-parallel-exe.json)。`core/config/frozen_manifest`、Store、策略适配层、TickFlow 请求和同步实现对基线零差异；冻结发布摘要仍为 `185541a4c226af123a36d113ca741c1b207a5413cd6fb6b4fd980381f0ff312c`。文本差异检查通过。

## 性能证据边界

`tools/benchmark_tickflow_parallel.py` 以 `mode=ro`、`query_only` 和只读事务读取 Aplus 当前数据仓的 dataset 元数据，筛选 TickFlow 前复权同日最新快照并核 SHA。只复制行情，不读取账户、计划或持仓。每轮独立 Store、空判断缓存，原 Service 完整计算六策略、逐文件 SHA、逐股提交；交错串行/并行顺序，对比完整业务报告、观察 payload/机会身份和扫描缓存摘要。保留 OS 文件缓存，不声称物理冷盘。

此子集测量没有复制全市场目录/停牌证据并执行全市场资格门禁，也不包括网络更新；不认证样本完整性。真实样本计时零命中，命中等价由独立 H2 合成结构和既有策略契约测试支持，不能混称“真实全市场零漏报”。最终原始计时只保存计数、摘要与时间，不提交行情或证券清单。

最终代码仅从先前保存在隔离目录中的固定副本重新取数，不再访问正式运行仓或服务器。192 只、2026-11-03、历史根数中位 504；每轮 1152 次原版计算，复用 0。

该参考不能外推为 3170 只的线性总耗时，也不能代替正式门禁、当前行情完整性、更新阶段或稳定时段安装版的一键盘前验收。正命中正确性另由两只 H2 的 Service 对照及双 EXE 离线探针证明；它们使用合成结构，不冒充真实行情命中。
