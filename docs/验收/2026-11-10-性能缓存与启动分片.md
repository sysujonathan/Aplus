# 验收记录：性能修复——数据层/图表计算缓存与启动分片

- 日期：2026-11-10
- 分支：lord/perf-cache-fixes（两批提交）
- 关联 Issue：#126
- 风险分级：R2（跨模块行为：GUI 数据读取、图表计算、启动编排；不涉及冻结策略、Store schema、信号计算逻辑）

## 问题与根因（实证摘要）

界面层无缓存/懒加载：catalog 冷 4.84s、code_names 冷 9.81s、load_candidates 冷 12.98s（热态毫秒级）；show_observation 每格全量重算策略且图像缓存 key 含 mode，候选↔自选交替看必然全价；启动在窗口构造期同步跑完全管线。全文见 Issue #126。

## 改动

第一批（数据层）：
- workbench/scan_cache.py：引擎指纹（scan_engine_version / calculation_versions）进程级缓存，键为输入文件 (path, mtime_ns, size) 集合，文件变必重算；latest_datasets 按 Store 文件+WAL 状态键缓存（返回深拷贝，读后复核键防并发写污染）。
- gui/data.py：catalog / code_names 进程级缓存，输入状态含 Store 提交（DB+WAL）、目录 CSV、插件文件；附显式 invalidate()。
- gui/match_list.py：load_from_store 管线缓存，键含最近扫描收据、形态收据及其工件文件状态、数据/引擎输入与标签；无形态错误时才写缓存。

第二批（图表与启动）：
- gui/chart_panel.py：进程级有界计算缓存（行情加载+prepare+calculate），键含观察、数据集记录/文件状态、策略版本/参数/文件状态、周期、截止日，与 mode 解耦；计划价位仍按原 mode 生成。
- gui/main_window.py：控件先建，after_idle → after(0) 依次执行自选 reload、候选加载与首图调度、布局恢复；构造期仅保留工具栏日期初始化、视图设置读取、既有异步控制器初始化；登录/版本检查未动。

## 验证证据（本地，Linux + xvfb，主仓库 venv）

- 第一批：shape/premarket 测试集与 pristine 基线完全一致（61 passed，3 个本机环境既存失败两边相同）；scan/premarket 集 80 passed。真实 runtime 库计时：catalog 0.02s→0.00s、code_names 1.56s→0.00s（第二次起命中）。缓存版引擎指纹与直算结果相等；临时目录改一个策略文件字节，engine_inputs 键随之变化（失效成立）。
- 第二批：计数脚本——同一 observation 两 mode 交替显示 4 次，calculate 只执行 1 次；行情文件状态变化、策略版本变化均触发重算；行情篡改被拒绝。广面测试失败集合为改动前基线的子集（无新增失败；基线 37 个失败均为本机缺 mplfinance/msvcrt、Xvfb 连接等环境因素）；shape 三件套复跑与既存失败集合一致。
- 未做：真实行情数据验证（本修复不改变信号计算，仅减少重复计算）、GitHub CI（以 PR 检查为准）、长期使用验收。
