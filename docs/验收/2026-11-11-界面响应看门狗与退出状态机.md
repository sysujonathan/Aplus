## 改了什么

- 新增 `gui/responsiveness.py`：Tk 主线程心跳（after 100ms 只打点）+
  守护线程看门狗；停顿越过 500ms/1s/3s 各记一条主线程堆栈到
  `%TEMP%/aplus_responsiveness.jsonl`（只有函数名/行号，无局部变量、
  无交易数据）；同一停顿回合不重复记，恢复后重新计。可用环境变量
  `APLUS_RESPONSIVENESS_WATCHDOG=0` 关闭。主窗口 __init__ 末尾启动，
  destroy 时停止。
- 真正退出改 after 驱动状态机（`_exit_from_tray` → `_begin_exit_flush`
  → `_poll_exit_flush` 50ms 轮询）：请求图表关闭后逐拍检查 ACK；
  全部关闭→收尾（取消任务、停托盘、destroy）；图表拒绝关闭（300ms
  宽限后仍未进入 closing）→静默恢复会话（含恢复托盘轮询）；15 秒
  超时→原警告文案+恢复会话。Tk 线程不再 `update()+sleep` 忙等。
  同步版 `_flush_embedded_charts` 保留给软件更新前的保存闸门（其
  契约与既有测试不变），本批未动。
- `workbench/shape_tasks.py::close(wait=True)` 增加 wait 参数：
  destroy 路径传 wait=False（协作取消已发出，未完成项交守护线程，
  不再同步无限等待）；其余调用点默认行为不变。
- `_close_for_version_update` 的 `service.pool.shutdown(wait=True)`
  改为 wait=False + cancel_futures（更新已在空闲预留后触发，不再把
  Tk 线程押在无界等待上）。

## 不应改变什么

- X 仍是 hide-to-tray；托盘不可用时 X 走真正退出（新状态机）；
  未保存绘图的 ACK/超时/恢复语义与同步版一致（警告文案未改）；
  不静默杀进程、不覆盖未保存数据；价格与冻结信号逻辑未动。

## 修复轮次（2026-11-11，CI 红触发）

- PR #138 的 GitHub CI 红：`tests/test_update_review_safety.py` 5 个失败。根因：本 PR 把托盘退出改成 after 驱动的状态机（`_exit_from_tray` → `_begin_exit_flush`），但该文件的两个假窗口（`tray_window()` 与原生定时器脚本内嵌的假窗口）只绑定了旧的三个方法，`_begin_exit_flush` 未绑定 → AttributeError；原生定时器用例因此走不到退出确认（Exception in Tkinter callback / deadline 超时）。生产代码本身无错，是测试假窗口未随重构同步。
- 修法：两处绑定循环补齐新状态机方法（`_begin_exit_flush`、`_poll_exit_flush`、`_finish_exit`、`_abort_exit`、`_resume_embedded_charts`），与本 PR 自带 `test_exit_state_machine.py` 的假窗口做法一致；不改生产代码、不改断言。
- 证据：本地 `test_update_review_safety` + `test_exit_state_machine` + `test_responsiveness_watchdog` + `test_chart_exit_recovery` 共 25 passed / 2 skipped（跳过的是 Windows-only 原生定时器用例，以 CI 复跑为准）；故意注入（恢复旧版绑定）3 failed、修复后 11 passed。
