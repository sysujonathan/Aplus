# PR84 安装中断恢复评审修正

评审基线 `f74ed69b9e1e787d9db7be0de4aadb414deb32b6`。仅修 P0 中断恢复与 P1 启动器维护，
沿用原 PR84，不改业务、冻结区、Store/schema、其他 PR 或正式日用安装。

## 已确认问题

- 原 worker 在 Setup 前写 pending 但没有阶段/PID；Popen 后才补 PID。助手异常退出/重启会留下无 PID 记录，
  原 recover_pending 永久返回阻断。原启动器还在恢复前检查 current EXE，当前文件损坏时无法恢复。
- `onlyifdoesntexist` 使启动器安装后无法接收修补。

## 修正契约

- Setup 前保存 `installing`、旧 EXE SHA256；Setup 完成、Popen 前及 Popen 后依次保存 `installed`、
  `launching`、`startup_wait`。四个原子持久化点中断均有可解释状态。
- 恢复持有更新与安装命名锁；安装器/更新器仍活跃则保留。没有 PID 也按目标 EXE 的真实进程路径检查，
  防止 Popen 成功但尚未落 PID 时误回退。
- 有匹配版本/提交/数据路径的 ACK 则确认完成。否则只在无活跃新版、阶段已知、旧 EXE 哈希相符时恢复旧指针。
  未知旧格式或身份不完整的记录继续安全阻断，不静默删除 pending；恢复不修改业务数据库。
- 稳定启动器内置同样的恢复决策，先恢复再读取 current，因此当前版本缺失或指针损坏不会隐藏可信旧版。
- Setup 改为可替换启动器，并同时检查桌面与启动器锁；不强杀，不强制重启替换。
