# 发布迟到事件跳过修复验收记录（2026-11-11，Issue #133）

## 改了什么

- `tools/release_preflight.py`：准入尾段重构。当前 main 与 head 不一致
  时，若事件是**身份已完整验证的 workflow_run**（官方仓库/主线/验收
  workflow 名称与路径/head_sha/conclusion 均已在前段校验）且经
  `/compare/{head}...{current}` 确认 main 确已前进越过 head（head 为
  其祖先），返回 `build=false` 并打印 `stale accepted main superseded;
  skipped`——identity 绿、build/publish 自动 skipped，不再把正常迟到
  事件显示成发布失败。旧 head 本身永远不会因此获得构建资格。
- 其余路径 fail-closed 不变：workflow_dispatch 仍要求当前 main 精确
  一致；main 只是被改写/回退（compare 非 ahead）仍报 ValueError；
  compare API 出错按未验证处理、显式失败；当前 main 精确一致但验收
  未过仍失败；非法来源/仓库/事件在前段照旧拒绝。
- `tests/test_auto_installed_release.py`：新增迟到合法事件跳过、
  祖先关系不可证时失败、dispatch+main 已动仍失败、CLI 写 build=false
  共 4 个用例；原 main_moved 用例改为“main 动了但非前进越过”仍须失败。

## 不应改变什么

- 不削弱 SHA 精确校验、版本递增、哈希与人工 main 门禁；不产生包/
  草稿/标签（跳过路径在查询 latest release 之前提前返回）；已发布
  的 #34（v2026.11.11.2）流程与产物不受影响；不碰策略与业务数据库。

## 验证证据（Lord 本机）

- tests/test_auto_installed_release.py 全量：**67 passed**（含新增 4）。
- 故意错误注入：临时禁用迟到跳过分支，2 个迟到相关用例立即变红；
  恢复后 67 全绿。
- 环境注记：本机 venv 此前缺 PyYAML（requirements-lock.txt 声明的
  依赖），已按锁文件版本补装后复跑。

## 未验收

  build/publish skipped）留待合并后由下一次自然迟到事件或验收方在
  Actions 中确认；本机无法模拟 GitHub 事件投递时序。
