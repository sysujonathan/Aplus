## 根因与修复

旧实现用 commit-ish 查询接口检查新标签是否存在，且只将 404 当作不存在。
GitHub 对不存在的 commit-ish 返回实际的 `No commit found for SHA … (HTTP 422)`。
旧测试替身把该情况返回成 404，未覆盖生产接口行为。

改用 `GET /git/ref/tags/<精确标签>` 检查存在性；[GitHub 官方接口契约](https://docs.github.com/en/rest/git/refs#get-a-reference)
明确未匹配引用返回 404。存在时仍通过 `/commits/<标签>` 解析最终 commit，兼容轻量及附注标签，
且提交必须等于已验收构建提交。没有把所有 422 当成标签不存在，也没有移除标签检查。
其他查询错误、错误提交、错误资产、版本倒退、主线前进仍停止；不覆盖既有 tag/Release。
真实只读核验另暴露 Windows 系统代码页下 gh 中文提交响应的 UnicodeDecodeError，
同轮将 gh JSON 解码固定为 UTF-8，不改变响应内容或发布许可。

## 发布和用户升级的独立边界

本修复须 PR 人工批准、合并和 main 自检通过后，新的主线构建才会使用它。
直接重跑旧失败 run 仍执行旧提交，不能证明修复生效；过时包也不能绕过“精确当前 main”要求公开。
