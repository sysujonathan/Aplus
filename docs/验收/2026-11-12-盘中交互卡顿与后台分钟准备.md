# 盘中交互卡顿与后台分钟准备

受验收实现提交：`f3baaa3fab3a18512c72505c9a81ce83e58195aa`。后续记录提交仅添加本文件。

基线：`main 70db3e5`（PR147 已合并，含 PR149 交易日历改动）。R2：界面并发和只读数据准备。本轮检查活动 PR 无重复开发。没有操作正式账本、覆盖本机安装或重新启动用户日用软件。

## 现场与根因

用户报告持仓输入、托盘显隐、盘中周期切换、首次拖动和斐波那契设置滞后，随后明确授权自行决定是否关闭卡死进程。

主 AplusApp 确认 `Responding=False`，窗口激活超时。保留进程树信息后，仅结束已核实的主进程和其图表子进程；复查 Aplus 进程已退出。未修改数据库或删除用户文件。强制退出不能保证未保存的输入／画线留存。

现有 `%TEMP%/aplus_responsiveness.jsonl` 当天共 1,243 条停顿记录，其中 1,229 条包含 `ChartPanel._intraday_tick -> _publish_intraday -> chart_minute_series`。多条超过 3 秒，堆栈落在 Pandas groupby、列选择和 `DataFrame.attrs` 的深复制。原路径直接运行在 Tk 主线程，托盘队列和持仓输入也因此得不到事件循环处理。日志仅包含函数栈，不含成交内容；原始日志与进程诊断留在本地，不上传。

另确认：新增持仓代码失焦会在 Tk 线程同步执行最新策略计划查询。托盘默认操作原来只有“打开”，没有切换隐藏行为。

## 修复范围

- 关注／候选图和持仓图共用有界后台分钟准备通道：一个正在执行、一个最新待执行请求，不逐条积压。Tk 只交付当前请求的结果。
- 按代码、页面 token、宿主和上下文检查迟到结果；停止图格、关闭自动行情及销毁窗口时失效。历史形态依旧禁止接收盘中分钟行情。
- 数值选择／聚合不携带 `attrs` 中整份一分钟传输信息；原始 quote、m1 保留在最终显示 payload。OHLCV 聚合公式及完整性条件未改。
- 策略计划查询移至后台。查询返回时若代码已变则丢弃；买点／止损／目标价已手填则保留人工输入，避免迟到自动回填。
- 托盘默认操作改为“显示／隐藏主界面”；显式 show、退出保存与更新期间保护保留。

不涉及冻结策略、Store/schema、扫描算法、供应商请求频率、实际成交或正式历史行情写入。没有为性能移除校验，也没有修改图表绘图语义。

### 性能对拍

使用同一份 13 个合成交易日、624 根五分钟数据，附带 640 条一分钟记录及报价。通过 `git show 70db3e5:workbench/live_minutes.py` 加载原实现，与当前实现分别执行 `chart_minute_series`，逐项比较完整返回值：**完全一致**。

本机一次计时：原实现 **7,816.6 ms**，当前 **796.2 ms**。这是此样本、此环境的计算耗时，不是所有设备的速度承诺；当前耗时也已移出 Tk 主线程。

`NeverCopy.__deepcopy__` 故障注入额外确认：数值显示过程不再复制无关 transport attrs；原始 metadata 对象仍留在源帧中。

## 正式版人工验收

1. 盘中开启自动行情，持续观察分钟数据；同时新增持仓，输入代码、价格、手数及税费，应能连续输入。取消测试表单，勿为测试创建真实成交。
2. 点托盘图标隐藏，再点恢复；右键退出仍应先完成图表保存。
3. 五分钟、小时、日、周之间切换；行情到来时不回跳，不串标的，原画线保留。
4. 留有左侧历史时，第一次左键拖动即可平移；全部历史已显示或已到最早边界时不得把无更多历史误判成拖动故障。
5. 斐波那契及其他已支持工具的设置、取消、确认和重开保存正常；白涨蓝跌、橙色 EMA、策略只读标注、提醒与回放不倒退。
6. 计划查询期间手填价位，返回后不被覆盖；切换代码后不带入旧标的计划。

本轮本地证据不能代替用户原设备、真实盘中长时间运行的最终验收。提交 PR 后不等待 CI，不自行合并或发布安装包。
