# 独立 PR 定向 CI 效率治理

## 范围与基线

- 类型/风险：开发、CI 治理，R2；只改选择器、边界测试、编译器步骤条件及对应说明。
- 主线基线：`8d336b801eda55636863194521542d006ee728d8`；实现与验证版本：`fb6f8e4801950240726d12cb673b25ea696ccefb`（后续仅补本记录）。
- 完成标准：受控 PR 映射可执行；未知/高风险仍全量；去掉已证实重复成本；独立 PR 人工评审，不自动合并。
- 不变契约：冻结字节、策略计算、真实交易数据、Store/schema、发布身份与门禁；`A acceptance / test`、PR/main push 触发和旧 PR 运行取消规则。
- 开工查看活动 PR110、108，均未修改本次 CI 三个文件。PR110 的导航/共享业务修改不纳入本分支。

## 可执行规则

精确文件表与测试命令以 `tools/ci_test_plan.py` 的 `MODULE_PATHS` / `MODULE_TESTS` 为准，避免再维护一份不同步的大清单。

- 所有定向范围仍包含选择器与版本契约；多范围并集，Python 测试文件稳定去重。
- 仅根 AGENTS.md、README、docs Markdown 与 docs/images 的常见说明图片可进入 docs；运行时 JS、品牌资产、任意 JSON/其他目录图片不因此获准。
- PA 包含共享数据/私密记录、会话切换、权限失效、OAuth/打包契约、导航竞态、输入法、真实双 WebView 与图表对照等现有专项。`pa_auth.py` / `pa_oauth_config.py` 自身仍 full。
- PR110 尚未合并的协作测试为单独精确条目；只有其测试/脚本变化才加入该文件，并同时加入完整 PA 范围。没有把未来任意 `test_pa_*` 自动放行；缺文件会让 pytest 失败。
- PA 的 scope Node 回归没有 pytest 包装器，显式执行；其余 Node 回归由选中的原包装器执行。先检查 Node 可执行，避免缺运行时而全部 skip。
- Git/event 无法证明范围、代码删除/重命名、未知文件/安全边界始终 full；改动标题/标签/正文不能改变选择。
- Actions 摘要显示范围、具体改动原因和实际命令；full 给出导致回退的文件/证据问题。未知范围、缺 Node、子命令失败和 pytest 零收集均不能返回成功。

## 剩余风险与后续工作

- 精确映射依赖人工维护；新文件或未来公共接口变化默认 full，需先补相邻契约再评审扩表。PA 范围有意保留较广专项，不能承诺固定耗时。
- PR110 的新测试/导航探针必须随业务变更保持一致；本 PR 不替其修改业务验收入口。两 PR 无代码合并顺序依赖，后续由 CI 发现真实交互回归。
- main push 的完整覆盖不变，仍可能触发完整正式安装包发行；纯文档合并成本也暂保留。未动 `installed-release.yml`、`release_preflight.py`、权限、版本分配或精确提交校验。
- 后续可根据新规则实际运行数据独立研究主线缓存复用、全量与安装包构建去重，以及纯文档发行成本；需另行证明精确 main 验收和正式 payload 可信关系，本轮不实施。
- 交付状态：实现与本地必要验证完成，提交独立 PR 后结束；GitHub CI 与人工评审在后台进行，**不代表已满足合并条件或已合并**。
