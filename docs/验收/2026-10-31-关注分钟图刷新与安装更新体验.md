# 关注分钟图刷新与安装更新体验

## 范围与结论

任务为 R2 界面与行情传输修复，基于 main `c1ba393848837393ec3cd340319e55fd2552d25e`；
产品提交 `87023cad1f4a436623b2655c9b0e01381ed84257`。
不改策略、供应商请求/冷却、扫描资格、Store/schema、备份/恢复或发布审批规则。
安装更新部分只增加下载字节通知和界面进度、明确显示原有目录选择页；不实现增量补丁或运行中热替换。

根因由实际代码路径及新增组合回归确认：手动关注先显示旧日K，后台 fetch 成功后再次
`EmbeddedChartHost.show()`，新 token 重开页面并恢复默认日K；原分钟数据去重键没变，
休市又可能不继续轮询，因此新页面丢失已送达的分钟数据。交易管理自动报价开关与这条通路独立。

同标的日K刷新现在通过独立的、绑定当前 token/标的/来源/复权的只读通知原位更新。
前端保留分钟序列、所选周期、缩放、绘图和回放帧；后端只更新绘图的行情坐标，保留保存版本与冲突基线。
真正重新开页时重新送入已有分钟帧，不等待交易时段到来。后台日K失败仍保留已有页面。
新增通知文件随该图表正常关闭清理。

盘前文字显示具体来源、更新/核对/扫描阶段和“已处理多少只、共多少只”，不再将来源结束数写成整体百分比。
下载进度在 Tk 线程展示，后台只传递实际字节计数并节流；大小/SHA256 和安装前正式发布复核保持不变。
