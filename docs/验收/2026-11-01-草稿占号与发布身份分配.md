## 真实故障与根因

[Windows installed release #7 / 41272984119](https://github.com/sysujonathan/Aplus/actions/runs/41272984119)在a75ba840上构建成功，publish失败，日志明确：artifact `13069468942`为`AplusSetup-2026.11.01.2-verified`，环境`APLUS_VERSION=2026.11.01.2`、`APLUS_COMMIT=a75ba840…`；`verify_uploaded`拒绝“Existing release does not belong to this exact official package”。

2026-11-01认证只读查询得到现存草稿Release ID `430334981`、tag `v2026.11.01.2`，target_commitish=`1991a1b0800d215d7f489b9e6a1a2af6eda7317c`（PR90主线），draft=true/prerelease=false。最新公开版本仍为`v2026.11.01.1`。新构建没有覆盖它，也不应覆盖。

PR91解决了草稿按tag查询不可见的问题，但版本分配仍在`contents: read`的build作业中；[GitHub官方API说明](https://docs.github.com/en/rest/releases/releases#list-releases)明确只有具有push访问权的调用者能取得草稿。于是新构建按公开列表再次分配了已被旧草稿占用的.2，publish持写权限能看见它，正确拦截不同提交。这不是本机版本比较问题，也不是应删除的安全检查。

## 最小修复及不变门禁

将现有准入与分配代码移到独立`identity`作业，显式contents写权限以完整读取草稿元数据，保持actions只读，不保留checkout凭据、不安装项目依赖或运行Setup/编译器。构建作业仍继承全局只读权限，使用identity输出的精确提交、version、sequence，且再次执行原main/pushCI准入。

发布作业、artifact ID绑定、版本顺序、精确最新main两次检查、标签/提交/上传字节一致、下载校验及线上发现逻辑保持原样。只接受官方main成功push或main手动触发，PR/fork/其它分支不能发布；A acceptance/test触发、测试范围、必需检查和取消策略未改。发布全程仍在同一不取消的concurrency组中。

对GitHub发布列表命令增加失败检查；错误不会作为空历史分配。不删除或改写旧.2草稿，不改已发标签/包，不把旧包改版本清单冒充新构建。修复经人工评审合并及main验收后，新正式构建应自动选择高于所有可见正式/草稿的号。
