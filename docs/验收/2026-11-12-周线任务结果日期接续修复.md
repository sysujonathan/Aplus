# 周线任务结果日期接续修复

- 类型与等级：R2 修复，范围为任务结束后的日期选择、候选日期库存与相邻 GUI 测试。
- 基线：`60e0ed77c6049a0ec5bc76fac2edf9c2a90039d0`，已包含 PR157。
- 实现提交：`bdad4814247147b09e5b294160f396391df03272`。
- 本地环境：Windows 11、Python 3.12.13，全部测试使用临时合成 Store，不读取正式数据库。

## 用户影响与根因

用户提供的周线一键任务报错为：`日期读取失败，保留原选择；点击此处重试：扫描日期未出现在已保存结果中：2026-11-12`。

2026-11-12 是周四。现有生产 `weekly_bars` 使用 W-FRI 标签，并排除标签晚于任务截止日的周线，所以该截止日的最新已收盘周线标签是 2026-11-06。任务报告的 `asof` 却是输入截止日 11-12；GUI 原先直接用它选择周线结果，日期列表不含该日，因而报错。此提示本身不能证明行情请求或策略计算失败。

周线扫描读取日线快照，通常不另存周线 dataset；如果没有信号，也可能没有周线 observation。因此除修正完成回调的目标日期外，默认周线日期库存需从当前来源的日线快照截止日投影出可选周线日期。该投影只用于导航，不生成信号或扫描成功记录。

## 改动与边界

1. 完成／部分完成的单独扫描、一键盘前任务，将周线输入截止日转换为现有计算规则对应的已收盘周线标签；日线日期保持原值。
2. 默认日期库存补充当前行情来源日线快照对应的周线标签，支持零信号结果显示。显式来源查询仍只列实际保存的观察结果，其他来源的新日期不混入。
3. 保留原有异步日期读取、迟到结果隔离、失败保留与重试流程；不改变冻结策略、指标、周线聚合、扫描服务、Store/schema 或行情下载。

## 交易员验收

1. 在非周五的交易日执行周线一键任务，结束后日期落到最近已收盘周线，不再提示截止日不存在。
2. 没有策略信号时可显示空结果，不报日期读取失败，不虚构候选。
3. 日线一键任务仍选实际日线截止日；切换行情来源后不看到另一来源的新增日期。
4. 保留旧日期手动切换与失败重试能力；真实下载或扫描的其他错误仍须单独显示和排查。
