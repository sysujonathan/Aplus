## 根因证据

当前安装版显示 `2026.11.11.3`。仅以只读连接核对当前绑定运行目录的任务回执，未执行真实全市场补拉、写入、迁移或复制正式数据库。

用户截图中的周线回执为 1,202 只复用、3,606 次新判断、1,995 只未齐未扫描。对应周线任务排除明细：1,986 只历史不足（约 108 根完整周 K）、3 只历史缺日、2 只没有数据、4 只尾部滞后。它是“部分完成”，不能把未扫描理解成无信号。日线尾部齐全与周线历史足够是不同条件。

原 `ordinary_update_codes` 只判断有无数据及尾部，未比较请求起点。已有约两年日线且尾部齐全时，续做进入本地核对；历史不足又不属于普通价格缺口修复，导致所需更早日线一直不下载。不能把所有历史不足都反复补拉，否则新股会循环请求上市前数据。

切股触发的候选计算、行情文件校验、名称和图表 boot 准备原来在 Tk 回调内；形态候选还同步生成 PNG。手动关注虽有行情读取线程，返回后仍在 Tk 生成 boot。布局自动保存的同步 Store 写入也可能等待行情任务释放写锁。右键选中和来源标签切换会间接触发同一图表路径。

## 改动

1. 候选和形态图表使用每图格一个有界读取器，仅保留最新待处理选择；清空、换来源、隐藏或销毁图格时取消旧选择。工作线程只读数据库、准备计算／boot，主线程应用最后一个结果和操作控件。
2. 手动关注同样在行情工作线程准备 boot；交互图不再生成不用的 PNG。兼容预览串行访问 Matplotlib 共享状态。已显示图表的后续历史读取失败仍保留原图。
3. Host 接收预备 boot，切换仍走原 token 和未保存绘图确认。子进程仍在旧图 flush 后通过 `refresh_workspace_boot` 重读文档，不以较早预读内容覆盖刚保存的画线。只读历史刷新继续保留分钟图和编辑状态。
4. 布局自动保存移至后台，通过原 `Store.save_ui_preferences` 写入。前次写入确认 revision 后才提交下一份合并后的视图；冲突不覆盖其他窗口。保存进行中暂缓新建／复制／切换命名布局等管理操作，普通切股不等待；人工绘图保存机制未改。
5. 续做规划比较请求起点与成功获取的 coverage 区间，并绑定 dataset ID。新请求需要更早历史时进入原有增量同步，衔接／完整性审计和最终扫描资格仍由原实现决定。已成功请求过上市前区间的新股不反复请求；三源分别验证。

## 人工验收与边界

1. 新版本发布后，在盘前更新行情期间，分别从匹配列表／关注列表连续切三只标的、右键；菜单和页面应能响应，最终代码与选中行一致。
2. 在“全部／量化策略／形态捕手”间往返，含无结果的标签；旧读取结果不能把新选择换回去。单图和四图各检查一次。
3. 给图表画一条线再切股，确认原保存确认、再次打开可见；后台日线返回不能把当前分钟图重开为日线。
4. 对已有两年日线但历史更早可获取的范围执行周线一键，首次补齐所需前段，再次复用；新股仍可显示历史不足。其余缺日／滞后／无数据仍在缺口明细中说明，不保证全市场零缺口。
5. 真实供应商补拉时长取决于网络、缺失范围和节流；本轮未提高并发或承诺固定耗时。后台化改善界面响应，不承诺计算零耗时。
