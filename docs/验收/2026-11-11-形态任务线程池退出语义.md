# 形态任务线程池退出语义验收

范围：Issue #140，R2；不修改策略、数据库结构、保存安全门或提交/取消接口语义。

## 实测结论

修改产品代码前先增加 `tests/test_shape_pool_exit.py` 的真实子进程用例。
子进程通过 ShapeTasks.submit 启动忽略取消的 worker，等待独立 Event 2.5 秒后自行释放；
另排队一个 future，验证非阻塞关闭取消排队任务。测试使用临时 Store，不读取用户数据库。

基线：close 返回耗时 0.0000 秒；脚本结束后进程仍滞留 2.661 秒；返回值 None。
基线测试 1 passed。修复后同一用例返回运行中的 shape 任务 ID，close 0.0000 秒，进程滞留 2.611 秒，1 passed。
这不是立即退出保证：ThreadPoolExecutor 的非守护线程及解释器退出 hook 仍会等待 worker。

## 改动

ShapeTasks 保留提交 future 与任务 ID 的映射，close 返回 shutdown 后仍运行任务的 ID 快照。
关闭继续请求协作取消；wait=False 继续取消排队任务；不强杀线程或提前写入成功/取消结果。
窗口 destroy 登记该快照并记录警告，说明进程仍须等待收尾。Service 未发现可复用的同类机制，未修改。
窗口保存确认及更新/托盘退出流程保持原样；快照并不宣称任务随后仍未结束。
