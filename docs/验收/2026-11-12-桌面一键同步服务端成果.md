## 改动与使用

| 文件 | 理由 |
| --- | --- |
| `workbench/sync_source.py` | 只读服务端 Store，按既有 snapshot hits 精确选观测，输出完整行、行情与目录，临时目录成功后改名。 |
| `tools/export_sync_source.py` | 提供独立 CLI，支持 runtime/asof/out，默认选最新已有快照。 |
| `workbench/sync_client.py` | 预检全批、版本锚与新鲜度、增量文件、单事务登记数据及同步 meta；失败记日志。 |
| `gui/toolbar.py` | 只增加普通「同步」按钮，后台执行后沿现有通知刷新，使用既有状态区显示结果。 |
| `tests/test_desktop_sync.py` | 用临时合成两股样本验证读写闭环、幂等、拒绝、回滚和用户数据隔离。 |
| 本验收记录 | 区分实现证据、环境阻塞及人工待验范围，并记录部署用法。 |

服务端在原盘前快照生成之后运行：

```sh
python tools/export_sync_source.py --runtime /path/to/server-runtime
# 可指定 --asof 2026-11-11 --out /path/to/output
```

默认输出 `runtime/sync-source/<asof>/`。目标日期目录若已存在，拒绝覆盖，保留旧的完整目录。源必须有对应 snapshot.json；观测缺失、行情缺失或损坏明确失败。latest_datasets 查询附带的 rank 不进入清单，保留真实表中 11 列。

桌面启动环境的 `APLUS_SYNC_DIR` 指向本地同步源目录本身（根下直接有 manifest.json），或上述日期目录的父目录；用户点「同步」即可。未配置显示「未配置同步来源」；忙时显示「正在忙，稍后再试」。不增加页面、设置或下载后再操作的步骤。同步结果显示在既有顶部状态区，完成时通知既有主窗口候选刷新入口。原按钮处理函数未改。

客户端已有 dataset id 完全跳过源文件读取及文件重写。本地较新的 dataset 仍由原 latest_datasets 排序选中。写文件前验证全部待写内容；目录为可变文件，文件/事务失败时恢复其旧字节或移除新建目录文件。数据库失败会上抛给 GUI；数据库登记回滚，允许遗留未引用的内容寻址行情文件。Store 的文件操作仍会留下 events 日志，这些日志不是交易状态或同步成功回执。
