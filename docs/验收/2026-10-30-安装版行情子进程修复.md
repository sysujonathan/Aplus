# 安装版行情子进程修复

## 事实、范围和风险

用户报告试用包点击“一键”出现“已有 Aplus 运行”后无行情更新。
代码链确认：BaoStock/TickFlow 共用 provider_process，原启动命令为
`sys.executable -u -m workbench.provider_worker <vendor>`。打包后 sys.executable 是无控制台
AplusApp.exe，而安装入口未分派行情参数，落入桌面启动，触发单实例提示并使行情管道退出。
另需处理 windowed EXE 的 Python stdin/stdout 为 None，不能仅增加参数分派就认为通信恢复。

按 R2 行情进程启动边界修复；不变更业务同步/扫描、限流/冷却、连接租约、策略、Store/schema、
数据绑定及审批规则。已先将最新 main `8926ca6`（含 PR85）合入本 PR，自动合并无冲突，保留图表子进程 EXE 入口。

## 改动

- 源码保持 Python 模块命令；安装版使用显式 `--provider-worker <vendor>`，参数仅接受三个既有来源。
- 无控制台行情进程从父进程继承的 Windows 标准管道恢复 UTF-8 输入输出；缺少管道则明确失败，
  不误用默认桌面入口；stderr 无有效管道时仅进入空设备，不污染 JSON 回执。
- 未识别的启动参数拒绝执行，不再次打开桌面。供应商协议和错误细节保持。
- 构建脚本增加新 EXE 的离线通信门禁：实际三来源分派、TickFlow/Tencent 无网络 login/logout、
  参数错误中文回执、父进程主动取消并终止自身子进程、未知启动参数退出。BaoStock 不做真实 login。
  门禁无外网请求、不构造正式数据 Store、不新增绕过冷却的生产入口。
