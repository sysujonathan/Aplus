# TickFlow 证书连接修复验收

## 使用影响与版本

修复 Windows 上 TickFlow 在下载前报告 `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`，导致单独更新和一键盘前均停止的问题。基于 main `37a7c3598b040657f63f6d3ac609cb77c2bee4d1`，本记录随修复提交；具体交付 head 由关联 PR 记录。风险 R2，仅修改 TickFlow 的 HTTPS 连接信任配置。

目标安装为 `Aplus_daily`，Windows / Python 3.12.13 / OpenSSL 3.5.7 / NumPy 2.5.3 / pandas 2.3.3；使用现有锁定依赖 `certifi==2026.7.22`。不修改 requirements 或锁定安装清单，不新增安装依赖。

## 已验证事实

- 2026-10-28 约 06:59—07:00 的正式任务回执表明：TickFlow 在 `instruments` 操作证书校验失败，随后进入原持久冷却；两个按钮走同一条连接。诊断只使用现有新工作台数据库的只读连接，不实例化正式 Store 或执行同步任务。
- 同一目标 Python 对公共 TickFlow 域名进行 TLS 握手：系统默认信任失败（verify code 20），现有 certifi 证书库严格校验成功，协商 TLSv1.3。此结果定位到信任链差异，不推断所有数据源都发生故障。
- 修复从 `ssl.create_default_context()` 开始，保留系统信任，再加载 certifi CA，并仅传给 TickFlow 的独立 `HTTPSHandler`。保留 `CERT_REQUIRED`、域名校验及直连设置；不修改全局 SSL 默认工厂，不提供跳过校验或失败后的不安全连接。
- 使用目标 `Aplus_daily` 的虚拟环境加载本分支修复代码，实际调用一次上海市场 `instruments` 公共接口：成功返回 **2,468 条**目录，约 **1.969 秒**，严格证书与域名校验均开启。仅在内存中检查响应，无行情下载、覆盖推进、正式数据库或运行配置写入。
