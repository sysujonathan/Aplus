# TickFlow 证书连接修复验收

## 使用影响与版本

修复 Windows 上 TickFlow 在下载前报告 `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`，导致单独更新和一键盘前均停止的问题。基于 main `37a7c3598b040657f63f6d3ac609cb77c2bee4d1`，本记录随修复提交；具体交付 head 由关联 PR 记录。初版风险判定 R2；安全复审发现旧 CA 信任问题后提升为 R3，包含证书依赖升级和完整安全回归。

目标安装为 `Aplus_daily`，Windows / Python 3.12.13 / OpenSSL 3.5.7 / NumPy 2.5.3 / pandas 2.3.3。本次将已有依赖升级并锁定为 `certifi==2026.10.23`，直接依赖下限亦为该版本；本机开发和目标安装的虚拟环境已实际完成该单一包升级，Python/NumPy/pandas 等其余依赖未变。

## 安全复审更正（替代初版信任设计）

初版提交 `32a1d2cb782f48aa135c6432816ee1f46b415db0` 把旧 certifi CA 加入系统默认上下文，连通性虽通过，但没有充分核查该 CA 库的安全公告。此方案不应合并，也不能沿用“连通即安全”的结论。

[官方安全公告 GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2) 确认旧版信任受影响的 `emSign ECC Root CA - G3`；本机旧证书库实际包含该证书，DER SHA-256 为 `86a1ecba089c4a8d3bbe2734c612ba341d813e043cf9e8a862cd5c57a36bbe6b`。Python 官方建议至少升级至修复版；本 PR 选择已发布的 [2026.10.23](https://pypi.org/project/certifi/2026.10.23/)。

最终实现仅从修复版证书库创建严格 SSLContext，不加载系统默认或环境变量 CA；既验证实际包版本，也拒绝仍含上述已撤销信任 CA 的受污染证书库。父进程与 HTTP 工作进程均对旧依赖明确停止。代价是 TickFlow 不再使用仅安装于系统的企业自签信任；此类 TLS 拦截环境须单独处理，不能自动降低证书要求。

依赖升级使用系统严格 TLS 下载 PyPI 官方 wheel，并验证官方 SHA-256 `e9b54de76e530bb6cf0ccd036787103acb58fd42ba930ea8bf948ddbaa2f61d1`，随后离线、无依赖更新地安装这一包。没有通过旧 certifi 扩大信任后下载更新，也没有关闭证书或域名校验。

## 已验证事实

- 2026-10-28 约 06:59—07:00 的正式任务回执表明：TickFlow 在 `instruments` 操作证书校验失败，随后进入原持久冷却；两个按钮走同一条连接。诊断只使用现有新工作台数据库的只读连接，不实例化正式 Store 或执行同步任务。
- 同一目标 Python 对公共 TickFlow 域名进行 TLS 握手：系统默认信任失败（verify code 20），现有 certifi 证书库严格校验成功，协商 TLSv1.3。此结果定位到信任链差异，不推断所有数据源都发生故障。
- 最终修复采用显式安全证书库创建 SSLContext，仅传给 TickFlow 的独立 `HTTPSHandler`。保留 `CERT_REQUIRED`、域名校验及原直连设置；不修改全局 SSL 默认工厂，不提供跳过校验或失败后的不安全连接。
- 安全复审后，使用目标 `Aplus_daily` 的虚拟环境和实际 `certifi==2026.10.23` 加载最终修复代码，再调用一次上海市场 `instruments` 公共接口：成功返回 **2,468 条**目录，约 **1.609 秒**；上下文含 **118 个** CA，受影响根证书不存在，严格证书与域名校验均开启。仅在内存中检查响应，无行情下载、覆盖推进或正式数据库写入。

## 不变边界、发布与回退

冻结策略及 manifest、GAP H2、五策略灰度授权、Service／Store、数据库结构、行情合法性／SHA／停牌／缺日检查均未修改。请求仍串行、至少 1.5 秒间隔、15 秒 HTTP 超时，原有恢复额度和冷却不变；不删除历史审计或失败证据。证书库损坏、未知签发者、证书过期或域名不匹配时仍停止。

requirements 与锁定清单升级将触发原更新器的人工安装提示；不得绕过此门禁。人工批准并满足必需 CI 后，维护者须确认目标环境实际安装修复版依赖，再人工发布代码并重启。本机目标环境的 certifi 已升级，但正在使用的正式程序代码尚未替换，未重新签发本机加速授权；旧进程需重启才能加载新包。已存在的冷却须自然结束，不手工清除。需要回退时按原更新回执恢复更新前代码并保留安全版本 certifi，保留行情和数据库，不重新安装已知受影响版本。
