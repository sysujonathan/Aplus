# 接续后字体缩放与更新失败提示

## 范围与契约

修复安装版先打开数据接续/恢复窗口后，部分盘前文字变小的问题；右栏宽度和行高随实际 DPI 调整。一起明确网络限流/超时及回退结果。并入已有发布草稿修复 PR，不另开 PR。

不改变系统分辨率、Windows 缩放设置、策略、行情计算、Store/schema、用户数据位置或发布校验门禁。冻结区逐字节不变。字体为局部 GUI R1；更新反馈覆盖相邻升级契约，不修改验收/包认证/迁移/回退条件。

## 根因与修复

- 伙伴设备为 2880×1920、200%。本机也在真实 192-DPI 环境复现：普通 `tk.Tk()` 数据接续窗口先创建并销毁后，主窗口的 Tk DPI 留在约 96；默认按钮字体变成 18 点，而显式指定的列表字体仍为 9 点，文字约小一半。新增真实欢迎→桌面字体断言在原代码失败（1 failed，2.15 秒），不是要求用户调整显示设置。
- 所有安装欢迎/恢复/重新定位窗口在创建首个 Tcl 解释器前使用与现有桌面相同的 Windows DPI awareness。继续使用标准 ttk 欢迎窗口，避免提前创建 ttkbootstrap Style 单例。主窗口列表行高及右栏宽度同时按实际 DPI 计算，避免正常 200% 字体被固定 26px 行高裁切。
- 本机更新收据显示目标为 2026.11.01.1，兼容接力阶段因 `HTTP Error 403: rate limit exceeded` 回退到 2026.10.31.2。只读查询证实匿名 API 额度 60/60 已用完，服务端恢复时间为北京时间 2026-11-01 10:50:47。没有打开用户数据库或替用户重复安装。
- 新反馈仅对明确的 403 剩余额度为 0 / HTTP 429 解释为限流，合理的服务端 reset 转为北京时间；真实超时解释为连接超时。检查失败仍是 unavailable，不冒充已是最新；更新失败收据包含目标与保留旧版，网络回退时告知用户。没有增加请求重试、绕过 API、缓存旧绿灯或放松任何校验。

## 验证

- 首轮字体相关五组：107 passed / 4 warnings，53.16 秒。
- 最终 DPI 顺序及真实 Windows 欢迎/新数据/恢复/取消/失败/再次启动、桌面布局：51 passed，14.10 秒。真实窗口 DPI 与 Tk DPI 比较，列表行高容纳真实字体；100% 原宽度与 200% 宽度边界均覆盖。
- 网络反馈、安装更新 UX、schema bridge 与发布策略：96 passed，13.89 秒。限流只发原查询一次，不重试风暴；不把普通 403 误报额度不足；坏 reset 不虚构恢复时刻。
- 升级助手追加 403/超时故障注入后，六个接力结果场景 6 passed，1.15 秒；断言没有创建迁移副本、原库原字节不变、只重启旧程序一次，收据和真实通知均写明目标与保留旧版。
- 已通过且未改变的相邻模块证据复用；最终组合 head 的 GitHub 必需完整 CI 才是合并依据。没有在伙伴设备直接运行新修复，没有宣称跨交易日长期验收。
