# 安装更新阶段与启动等待提示

## 范围与基线

修复类型：安装更新体验。基于 main `2ed114acab1d51f286f038aa86e30f5a3d71fd94`；开工查询活动 PR 为空。
用户最初要求更新期间显示阶段与已用时，随后明确简化为一个统一的等待弹窗，不显示细分阶段，明确完成后自动打开、无需重复点击快捷方式；以后者为最终需求。
涉及更新助手线程调度和启动确认，按 R3 完整本地回归。未修改策略、冻结清单、Store/schema、行情计算、下载来源或发布门禁。

本机 11.01.1 的真实既有更新收据表明：16:42:02 第二阶段助手就绪，16:43:02 创建迁移副本目录，16:46:04 副本验证通过，16:46:22 主界面确认启动。
旧版接续窗口看到 ready.json 即关闭，其后备份/校验/迁移期间没有可见提示。本次未重新操作正式数据库来复现；正式数据未打开、未迁移。

## 最终行为

- `--installed-update` 进入独立助手进程自己的原生 Tk 窗口；事务在该进程的工作线程中运行，GUI 留在主线程。
- 提示窗口实际显示后才开始原更新事务，避免 ready.json 让旧主界面先退出而新提示尚未显示。
- 内部只读回调保留真实状态以决定何时结束提示；用户再次要求缩短文案后，所有正常等待状态统一显示“正在更新，请稍候。完成后自动打开。”和持续已用时，不向用户展示任务细节。
- 使用活动条，不伪造完成百分比。
- 普通关闭按钮只重申“完成后自动打开，无需重复点击快捷方式”，不在工作中取消更新。
- 仅原有完整身份匹配的 started.json 可结束提示。助手就绪、进程已创建、已过60秒或 completed 字样单独存在都不等于主界面已显示。
- 主界面和兼容引导的启动确认增加实际窗口映射检查。延迟确认后仍继续等待；失败恢复状态保留明确错误与可关闭提示，未处理的助手异常另存事务目录 progress-error.log。
- 显示回调出错被隔离，不改变原校验、数据保护、安装、迁移、回滚与清理流程。进度窗口不创建 Store，不拿业务单实例锁。

## 发布和适用边界

本轮没有替换用户本机安装，未构建或发布正式新版本，未等待 GitHub CI，未创建 PR。此前 PR93/94/95 已合并，无法继续向原 PR 追加本轮代码。
旧安装版第一次下载修复版时，尚未被替换的旧更新助手无法追溯增加进度窗口；新版接管的8→9阶段会使用新助手，安装修复版后的后续更新才具有完整助手进度。
跨版本数据保护可能本来需要数分钟，本轮解决等待透明度，不通过跳过备份、逐表核验或完整性检查来提速。
Win10 伙伴的 TLS 超时未在该设备复现，本轮不声称已修复网络连接问题；完整冻结 EXE/Setup 实机升级闭环和伙伴 Win10 UI 属正式发布前后验收，源代码原生窗口验证不替代这些结论。
