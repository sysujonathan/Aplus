# 首屏启动与手动关注K图

## 日常体验

启动默认最大化，可正常还原与缩放。盘前界面先显示已有候选和关注；完整性在后台核对，显示“正在后台核对完整性”，不是已通过验收。第一次打开盘后回测、策略迭代或交易管理时再构建对应页面；后台显示检查不替代真实更新／扫描前的完整性门禁。

关注列表标题右上角“＋”接受六位股票／ETF代码，或通过名称匹配后选择标的；备注可选。没有策略命中、没有行情时也能先关注。原有关注按代码去重，重复添加只定位／恢复，不覆盖原扫描锚点或备注。手动关注没有伪造的observation，不创建人工计划、成交或仓位；原扫描关注保留自己的策略依据。

点击手动关注后，在现有多图区域显示K线，保留日／周切换、TradingView跳转和A++图表工作区。手动关注不显示策略命中标签或策略交易计划；建仓时的人工计划仍在持仓管理填写。

## K线获取边界

- 优先读取当前来源已校验的本地日线，标明实际日期及复权口径；已有图先显示，过期时后台更新，不使桌面等待网络。
- 缺少本地行情时只获取当前这一只的两年不复权日线。股票使用当前可更新来源，ETF使用已有BaoStock按需通道；腾讯只保留归档读取，不恢复历史更新。
- 按需K线单独写入不可变`watch_history/<source>/<code>/<sha>.csv`，现有meta仅索引该来源／代码的图表缓存。它不登记到datasets、coverage或quality，不加入universe、不授权扫描，也不拼接不同来源价格。
- 取数先检查同一个ProviderGuard，仍用原供应商适配器、请求间隔及OS连接锁。黑名单、403、429、超时写入原冷却；一律不自动重试或改用另一来源。连接已占用时及时说明，不新增并行连接。
- 同一来源的多个图格在本机串行排队，轮到后重新检查冷却；前一个请求触发限制时，后续不再连接。TickFlow新会话持有原OS连接锁后先等待完整1.5秒请求间隔，等待可取消；取图结束或被取消后，再完成最多1.5秒交接间隔才放行后续业务请求，避免子进程重建使间隔被重置。
- 同一目标日已成功查询但末日仍较早时保留实际日期，不虚报最新、不自动循环请求；可主动点图格“更新K线”再查。文件损坏不显示为有效行情、不覆盖已有同名损坏证据。
- 切换标的、翻页或关闭窗口会取消过期请求；晚到的结果不覆盖当前图。数据与绘图在线程中完成，Tk控件只在主线程更新；后台线程不持有窗口引用。

关注联网读取尚未结束时不能替换软件代码；升级预留期间也不能新开关注网络请求。原数据结构版本8及所有既有保存方法保持不变。

用户主动启动盘前／研究任务时，先取消正在获取的关注K图，再在后台等待它安全释放连接后执行任务；不会阻塞提交按钮或抢着连接。任务执行期间仍可看本地K图，但不新开关注取数请求。

## 验收

新增回归覆盖默认最大化、慢完整性核对不阻塞首屏与其他控件、隐藏业务页按需加载、手动添加及去重、无observation看图、来源隔离、独立缓存重开复用与损坏拒绝、冷却先于连接、限制不重试、取消不保存、升级空闲边界。测试仅使用临时Store及模拟供应商，不读写正式账户、不重新下载正式行情或重扫。

正式环境的完整启动耗时、真实供应商响应及长期使用需分别验收，不能拿合成窗口或模拟请求结果代替。初步只读排查发现，旧首屏的约3197只股票状态证据核对可占数秒；本轮优先移除首屏等待，不删证据、不放宽扫描校验。
