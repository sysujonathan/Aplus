# 盘前快照分发（服务端备好、客户端只取）

第一版：把某日一键同步+扫描的结果导出为客户端可直接消费的结构化快照，
并配一个最小只读获取方式。服务端（本机定时任务）备好，客户端只取，
不跑同步、不跑扫描、不写回服务端。

## 产物

默认写到 `<运行目录>/snapshots/<asof>/`（`A_WORKBENCH_HOME` 未设时即
`~/.local/share/Aplus/runtime/snapshots/<asof>/`），含两个文件：

- `snapshot.json`：机器消费。`kind=aplus-premarket-snapshot`，`schema_version=1`。
- `index.html`：同内容的可读清单，无脚本、无外部资源，直接用浏览器打开。

## 快照内容

- `asof` / `generated_at` / `source` / `boards` / `strategies` / `timeframe`
- `engine_version`（扫描引擎摘要）与 `frozen_digest`（冻结清单摘要）：
  快照锚定到当次扫描实际用的策略版本，服务端换策略版本后旧快照
  不会被误认成新口径的结果。
- `complete`：是否全范围完成；`false` 时 `notes` 写明缺口。
- `coverage`：范围只数、可扫描只数、停牌只数、排除只数与分类
  （`input_gap` / `missing_dataset` / `stale_tail` / `insufficient_bars`）、
  评估次数（成功／复用／实算）、同步更新只数与同步错误数。
- `hits`：按策略、代码排序；每条含代码、名称、策略、版本、建仓日、
  入场／止损／目标；GAP H2 另带 `plan`（SL1、MM、前序开放缺口数、
  待触发状态、初始风险）。名称取自本机目录清单，不联网。
- `excluded`：被排除的全部代码、分类与原因（截断 200 字）。
- `jobs`：盘前／同步／扫描三个任务 ID，可回查 `jobs` 表完整回执。
- `timing_seconds`：同步与扫描耗时（秒）。

## 用法

```bash
# 导出（只读：只读 Store，不写数据库、不碰策略、不联网）
python tools/export_premarket_snapshot.py [--asof 2026-11-09] [--out DIR]

# 只读提供已导出的快照目录（默认只绑本机，仅 snapshot.json 与 index.html）
python tools/serve_premarket_snapshot.py --dir <运行目录>/snapshots/2026-11-09 [--port 8000]
```

客户端消费：读 `snapshot.json`（校验见 `workbench/snapshot.py:load_snapshot`），
或直接打开 `index.html`。快照是只读事实源：自选、标注、持仓不在快照里，
仍由客户端本地 Store 管理（见下节）。

## 边界与后续

- v1 只支持单数据源的一键盘前结果；多源结果明确报错，不拼不完整快照。
- v1 不改 PC 客户端：客户端改为「取快照」是第二阶段（见
  《Aplus 架构升级评估 2026-11-09》），届时以快照的 `engine_version` /
  `frozen_digest` 校验口径一致后再展示。
- 自选／标注跨端一致性不在 v1：它们仍在各端本地 `workbench.sqlite3`
 （`watchlist` / `pa_notes` / `plans`），服务端只下发只读快照，
  不接受写回；跨端写路径需要独立的身份与合并设计，另行决策。
- 快照目录不进仓库：`runtime/` 已在忽略范围；`snapshots/` 在运行目录下，
  与行情库、数据库同级。
