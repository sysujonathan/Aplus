# TradingView 图表工作台重构方案

范围与逐项验收以 [TV 原始需求与验收清单](TV原始需求与验收清单.md) 为准。用户仅暂缓分钟数据源及其依赖功能；本文的设计建议和已有代码不表示交易员验收完成，未完成的非分钟功能继续在本次范围内。

## 交易员使用结论

策略扫描与自选标的应作为选股导航，主工作区默认是一张可以持续分析的完整图表。交易员从 GAP H2 等策略结果点入股票后，先核对策略证据，再在同一张图上画趋势线、缺口、斐波那契、通道和多头仓位，并设置提醒。切换到其他股票或下次打开时，原标的的人工图形、指标参数、缩放位置和提醒仍在。

因此桌面不再把“策略提醒挂单页”和“A++ 图表”设计成两套割裂入口。候选、关注、持仓、已清仓共用同一个图表内核；右侧面板只改变上下文，不更换图表操作逻辑。多图保留为快速扫描视图，选中任意一格后进入同一套单图分析工作区。

## 页面结构

### 顶部全局工具栏

从左到右依次为标的、周期、图表类型、指标、布局、提醒、回放、撤销／重做、布局名称、快照和侧栏开关。图标全部使用统一线性 SVG，视觉尺寸 20–24px，点击热区不小于 36px。

当前只有日、周、月真实行情时，5 分钟、1 小时和 4 小时保留位置但禁用，并在悬停时说明“尚未接入分钟行情”。只有接入真实分钟源或用户导入并通过校验的分钟 CSV 后才可用 Bar Count。

### 左侧绘图栏与常用浮条

左侧保持 TradingView 的肌肉记忆顺序：光标、趋势线、斐波那契、几何形态、文字、图标、测量、框选放大、框选缩小、磁铁、锁定、显隐、移除和收藏。常用浮条固定包含用户日常使用的 11 项：斐波那契、多头仓位、水平射线、趋势线、空头仓位、矩形、上下箭头、箭头、多段折线和平行通道。浮条通过左侧六点抓手拖动并保存位置。

工具采用明确状态机：空闲、准备落点、绘制中、对象选中、整体拖移、锚点拖动、框选缩放、平移和回放互斥。默认完成一个图形后自动回到光标，不连续绘图；多段折线逐点落位并双击完成。磁铁打开时，仅在端点靠近K线时吸附该根K线的开高低收。Esc 结束绘制，Delete 删除选中对象，Ctrl+Z／Ctrl+Y 撤销或重做人工图形；策略证据不进入人工撤销栈。

### 主图

默认主题按用户实际 TradingView 页面：`#0B0B0B` 背景、`#1F1F1F` 网格、白色上涨 K、`#2962FF` 下跌 K、`#FF9800` EMA20。右侧价格轴与底部时间轴直接参与交互：拖动价格轴改变纵向比例，拖动时间轴改变横向密度，双击恢复自动范围；鼠标所在位置显示十字线、价格、日期和对应 OHLC。主图区空白处按住左键直接平移，方向与图形跟手一致。鼠标进入图表中下部中央约 500px 宽、时间轴上方约 110px 高的区域时，临时显示缩小、放大、向左、向右和重置五键；离开区域后隐藏，不遮挡日常标绘。

“重置图表视图”恢复横向 204 根实际K线、最新K线右侧约 12 根K线宽度的观察空间，同时恢复纵轴自动范围。滚轮、时间轴拖动、底部加减和框选缩放都改变可见根数，因此K线实体和影线宽度必须同步变化；不能只放大坐标文字或绘图覆盖层。

图上信息分为五层，层次不可混用：

1. 行情层：K 线、成交量、EMA 等指标。
2. 策略证据层：冻结策略生成的结构、标记和计划，只读。
3. 人工图形层：交易员画线、缺口、仓位工具与文字，可编辑并持久化。
4. 提醒层：价格线和本机收盘提醒，可编辑但不自动下单或外发消息。
5. 临时交互层：十字线、选中框、锚点和绘制预览，不保存。

### 右侧上下文栏

默认显示“策略匹配 / 自选标的”两个导航页签。策略候选卡只保留选图需要的信息；当前标的的 Entry、SL1、MM、风险和收益集中放入决策卡。对象树列出策略证据、指标、人工图形和提醒，支持逐项显隐、锁定、编辑和删除。

持仓与已清仓入口复用相同面板位置，改为展示实际买点、综合成本和已保存止盈止损。图表内核、人工对象和操作习惯保持一致。

## 弹窗和关键交互

### 对象属性

单击选中对象，显示浮动快捷条；拖动图形移动整体，拖动圆形关键端点调整结构；双击或对象树“管理”打开完整属性。属性入口统一为“样式、坐标、可见性”三页，但样式内容必须由工具定义：斐波那契管理级别与标签，仓位工具管理利润／止损区，上下箭头管理大小与透明度，矩形管理边框与背景，多段折线管理节点。颜色使用色板选择，线宽和线型可直接设置。修改后立即保存到对应标的图表草稿。

### 提醒

闹钟加号打开创建提醒：选择标的或指标、条件、阈值、频率和名称。第一阶段只在新 K 线收盘后判断，不补发历史事件，不外发消息。创建后提醒同时出现在图上的价格线和对象树。

### 回放

回放进入独立状态：第一次点击先打开“选择日期”，日线时间固定为 00:00，可在月历、日期输入或“第一个可用日期”中确定起点。确定后截断未来 K 线，显示虚线边界和“回放”水印；底部控制条按 TV 顺序提供日期、播放/暂停、逐根前进、0.1x–10x 速度、日线更新周期、更新至最后一根和退出。播放/暂停同时支持 `Shift +`。回放期间策略证据只显示当时已经成立的内容；人工图形按创建K线决定是否可见。退出前询问是否保存回放位置，离开后恢复当前行情与进入回放前的视口。

### 快照

相机在用户点击后生成当前缩放范围的完整图表 PNG，优先直接复制到系统剪贴板并给出成功提示；浏览器未开放图片剪贴板时才进入预览保存。快照包含行情、策略证据和人工图形，不包含个人侧栏，生成过程不上传数据。

### 显隐与移除

左下眼睛菜单可分别隐藏图形、指标、策略证据或全部内容，隐藏不删除。垃圾桶菜单只能移除人工图形和指标；冻结策略证据始终不出现在删除清单中。

## 数据持久化与身份

图表状态继续由 `workbench/store.py` 写入本机运行仓。状态以“证券代码 + 行情来源 + 复权口径”为行情身份，同时需要增加证券级人工对象身份：交易员在同一证券上的主观画线默认可跨来源显示，但必须记录创建来源与复权坐标；切换来源或复权后若价格坐标无法可靠换算，则显示为“待核对”，不静默移动。

建议保存结构：

- 证券视图：当前周期、可见根数、横向偏移、纵向比例、右侧面板状态。
- 指标：类型、参数、颜色、可见性、顺序。
- 人工对象：类型、锚点时间和价格、样式、锁定、可见性、创建来源与复权口径。
- 提醒：条件、阈值、周期、最后判断 K 线和启用状态。

数据库结构若需变化，只能由 `workbench/store.py` 升级；升级只增加表或字段，不删除现有图形和用户记录。

## 技术落地

保留 Python 的行情、策略、计划、提醒状态机和 Store。图表展示改为本机嵌入式 Web 视图：K 线和高频交互由 Canvas/WebGL 图表层完成，工具栏、对象树和弹窗由 HTML/CSS/SVG 完成，Python 与页面通过受控桥接交换 JSON。

当前 Tk Canvas 版本仍可作为回退入口，但不再继续堆叠字符图标或位图叠加功能。它无法稳定复刻价格轴拖动、对象锚点、复杂弹窗、高清缩放和跨平台一致视觉。

推荐目录边界：

- `gui/chart_shell.py`：创建本机 WebView、窗口生命周期和 Python 桥接。
- `gui/chart_bridge.py`：读取行情、策略证据、持久化图形、管理提醒。
- `gui/chart_web/`：前端源码与发布后的本机静态资源。
- `workbench/chart_workspace.py`：继续负责文档校验、分钟聚合、撤销语义和提醒状态机。
- `workbench/store.py`：唯一数据库升级和保存入口。

前端图表库仅负责基础 K 线与坐标变换；斐波那契、仓位工具、路径、平行通道和 GAP 证据均由 Aplus 自己的可测试图元实现，避免依赖第三方付费绘图组件。

## GAP H2 视觉契约

GAP 区域、Gap Floor、Gap 标签与引线统一使用灰白色 `#CBD5E1`。区域保持 1.2px 虚线、透明度约 0.6、无填充；Floor 为同色 1px 实线、透明度约 0.5；Gap 标签使用深色底与灰白引线，不使用蓝字白底框。缺口几何与策略计算不变。此前文档把恢复样式写成蓝色空框是错误口径，以用户明确要求的中性色标注为准。

BO、H1、H2、MM low 和 Gap Floor 的文字及引线继续使用灰白中性色，避免与上涨／下跌 K 线混淆。Entry、SL1、风险收益卡、H2 真实触发 K、失效与过期语义不因本次视觉恢复而变化。

5. **等待真实数据源**：接入经确认的真实分钟源后启用 5 分钟、1 小时、4 小时和 Bar Count；未接入前保持禁用。用户手工导入且通过连续性校验的真实 5 分钟 CSV 仍可在兼容工作区研究，不会由日线伪造分钟线。

## 验收口径

以下为 PR49 的历史评审结论。PR49 已于 2026-10-16 合入 main（`9ae9b9e`）；下文“尚未合并／未发布”为当时评审时点的记录，不是当前状态。这些保护继续生效。本轮未提交的主页面与样式改动不因此视为已合入、已发布或已验收。

PR49 评审补充（2026-10-16，尚未合并）：人工图形以原始日期／价格作为保存坐标，各周期索引只用于显示；往返日／周／月不得改写锚点或创建日期。策略证据使用明确的 W-FRI／自然月所属区间，日期缺失不回退到第一根 K。提醒由前端传入当前周期，按上海市场收盘口径从已完成序列初始化游标，不能使用正在形成的周／月 K 标签。保存队列使用不可变快照，关闭前等待 Store 确认；失败保留窗口。回归同时执行实际 JavaScript 切换／保存／提醒／证据渲染和 Python Store 往返链路。

第二轮评审修复（同日，未发布）：WebView 不停用全局提醒监视器。桥接保存以打开时及本窗口最近成功保存的画线／设置为基线，外部只更新提醒时保留最新提醒并使用 Store 原有原子版本检查提交；读取与提交间再次推进提醒最多重读三次，其他窗口修改画线／设置仍报冲突。新增提醒写入也遵守同一基线保护。兼容 Tk 入口过滤 WebView 专用场景参数，补齐文字／价格范围的对象标签、图上绘制和快照，读取及关闭不改写原对象。新增已完成周期首根触发、实际监视器读图／写入竞争和 WebView 失败后实际 Tk 初始化回归。

第三轮评审修复（同日，未发布）：提醒创建与轮询共用正式行情读取入口，核对来源／复权并使用原快照哈希校验，不使用候选的历史截断图。新提醒独立保存创建时间水位 `active_after`，晚到的创建前收盘行情只推进游标，不能补触发；旧提醒保留既有游标及记录，不猜测其原创建时间。周／月聚合另核对日线尾部覆盖最后交易日，拒绝把周四快照的周五标签当成已完成周 K。完成时刻在已知交易所日历范围内取最后交易日 19:00，消除周末月末跨月等待；未知年份保持保守。兼容图表创建及检查使用同一入口。回归覆盖历史候选、正式源自身过时后的晚到行情、周五缺日、月末周末、来源／复权不匹配及创建水位的保存与并发合并。已同步 PR48 合入后的 main；冻结策略、Store schema、观察／计划及账本未改。

- 1920×1080 和 2560×1440 下，工具栏、主图、价格轴和右侧面板无截断或重叠。
