# MTR 快速拒绝灰度说明

## 对交易员的影响

本功能只减少“末根 K 线肯定不可能成为 MTR 信号 K”时的 MTR 内部结构计算，不改变行情读取、SHA-256、历史质量检查、公共指标、其他五种策略或已有交易记录。

合入代码后默认仍为 **OFF**，日常扫描继续完整执行冻结 MTR。没有人工批准和精确版本授权，程序不会采用快速结果。

## 为什么末根条件是必要条件

当前冻结版 MTR 的正式候选必须同时满足：

- `signal_at_end` 只读取策略结果最后一行；
- 冻结 MTR 把 `signal_mtr=True` 写在实际信号 K 所在行，而不是结构被检测到的行；
- 该信号 K 必须有价格区间、收盘高于开盘，并在冻结版浮点容差内收于最高价。

因此，末根 K 线不满足上述信号 K 条件时，历史较早出现的信号 K 或末根才检测到的结构都不能变成当日正式 MTR 候选。快速门禁判断的是最终正式输出的必要条件，不是只看一列历史原始形态。

## 三类运行方式

- **OFF**：默认方式。缓存键、完成阶段复用和 MTR 调用保持原版路径。
- **SHADOW**：仍以完整冻结 MTR 的结果为正式结果；对可拒绝样本记录旁路比较，不节省 MTR 计算时间。
- **CANARY / ACCELERATED**：只有精确绑定和人工授权同时通过后才可采用快速拒绝。末根可能成为信号 K 时仍完整执行 MTR；被拒绝样本按确定性比例继续执行原版对拍。

灰度开关不在 GUI 暴露，避免普通运行误开。维护者使用以下环境变量：

- `APLUS_MTR_FAST_REJECT_MODE`：`OFF`、`SHADOW`、`CANARY` 或 `ACCELERATED`；
- `APLUS_MTR_FAST_REJECT_APPROVED_BINDING`：当前代码、策略、依赖和运行环境共同生成的 64 位绑定号；
- `APLUS_MTR_FAST_REJECT_CANARY_RATE`：`0` 到 `1` 的确定性抽样比例，默认 `0.05`。

绑定号可在目标运行环境中只读查询：

```powershell
python -c "from workbench.mtr_acceleration import current_binding_id; print(current_binding_id())"
```

绑定号包含冻结发布版本、MTR 计算依赖、正式输出适配层、扫描服务接入、本加速器源码以及 Python、NumPy、pandas 和操作系统版本。任一项变化后，旧授权自动失效并回退原版。

## 回退和熔断

以下情况直接执行完整原版：版本或运行环境不匹配、未提供精确授权、输入或公共指标不在已验证域、门禁判断异常、绑定已经熔断。

CANARY / ACCELERATED 的抽样原版只要出现以下任一可信差异，就立即停止本轮后续加速，并在现有 `meta` 和 `events` 中保留绑定号、样本摘要、原版结果或异常：

- 门禁认为可拒绝，但原版产生正式 payload；
- 门禁认为可拒绝，但原版报告业务异常。

熔断不新增数据库结构。下一次启动读取到同一绑定的熔断证据后继续走 OFF 原版。非 OFF 模式使用独立缓存和完成阶段身份，不读取或污染 OFF 的正式判断缓存；切回 OFF 不依赖清库或删除历史。

## 正式启用前的审批条件

本 PR 只交付默认关闭的灰度能力。正式启用至少还需要：

1. 在准备启用的 Windows 正式运行环境重新生成并人工批准精确绑定号；
2. 使用当前 main、真实可扫池和多交易日快照完成 SHADOW 零差异对拍；
3. 对信号、无信号、信号 K 与检测 K 不同、浮点边界、双来源、缓存和恢复场景比较完整 payload、机会身份、日期、价格、评分和异常；
4. 先以有代表性的确定性 canary 比例运行，确认没有熔断或无法解释的回退；
5. 单独批准模式和抽样比例，并保留将模式改回 OFF 的一键回退办法。

生成行情与隔离库测试不是正式行情验收。仓库未附带用户的长期真实行情快照时，不能用短历史或合成数据替代全市场长期体验结论。
