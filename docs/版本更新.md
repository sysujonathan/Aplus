# 桌面版本检查与安全更新

## 日常怎么用

版本窗口先展示状态结论、正在运行的版本、主线版本、检查日期和简明更新摘要。手动检查和自动提醒共用同一个窗口；当天缓存只作为新版线索，程序会在后台自动联网重新确认。满足条件时提供整行高亮的“立即更新并重启”，点击后不再重复询问，自动完成备份、更新和重新打开，成功时明确显示完成结果。不满足条件时按钮禁用并明确下一步。“重新检查”仅用于用户主动再次核对；“更新日志”直接打开离线逐PR日志；分支、完整提交号和本机定制信息收在“技术详情”，不要求普通用户理解Git。

灰色按钮不等于都在等待检查：主线自检进行中时提示稍后重新检查；失败或取消时提示等待项目负责人修复；缺少结果时提示稍后检查，持续缺失则联系提供软件的同事。需要人工安装时按钮直接显示“本次需要人工安装”，说明继续等待或反复检查不会解锁，请联系提供／部署Aplus的同事协助，旧版可继续使用，不要删除行情或交易记录。本机修改、开发安装也分别说明需要保留什么、联系谁；这些文案不放宽原更新许可。同一版本号对应不同代码提交时只说明“同一版本号下有代码修订”，不伪造新编号。

编号规则为日期＋PR号，例 `v2026.10.10.29`；预览版明确标注，不能因为数字更大就允许替换。`release_catalog.json`是唯一编号/摘要源，`docs/更新日志.md`为相同内容的文档视图，测试检查一致。PR1未发布，PR12/13随PR11、PR23随PR22纳入主线，不虚构独立发布。旧1.1.4为功能阶段名。未来PR在清单中追加版本及摘要；正式合入后维护发布状态，精确main提交及CI始终决定是否允许更新，不依据编号大小。

软件内的“更新日志”按新版在前展示：版本标题大号加粗，日期、PR号及发布状态用较淡的小字，每项更新用圆点列出，版本之间以横线分隔。长说明自动换行，窗口缩放时横线随内容宽度调整；不会显示 Markdown 标记或冗长的链接原文。此处仅排版同一份离线版本清单，不改变版本事实、更新许可或交易数据。

“正在运行”在窗口启动时固定记录；磁盘代码在运行中更换时显示旧运行版本并要求完整退出托盘重开，禁用直接更新，不能把磁盘SHA当作已加载新版。旧main没有版本清单时，仅对有完整提交证据的历史版本回溯编号；未知旧版显示未编号，不猜编号。新版清单从检查目标的准确Git提交读取，不拿本机预览的版本号冒充正式新版；编号缺失不放宽Git/CI门槛。

顶栏右侧“版本更新”用于主动检查本地代码与GitHub主线。每次桌面启动并完成首屏显示后，会延迟数秒在后台静默检查；没有新版、离线或验收未通过时不弹窗。软件长时间不重启时，点击“策略扫描”后会顺带进行每日低频检查，每个上海日期最多一次（失败也不反复请求）；一键盘前进入扫描阶段使用同一入口。仅更新行情／补拉不会额外联网检查版本。检查不占行情进度；当天缓存发现新版时会自动进行一次新鲜核验，通过后把按钮改为“有新版 · 查看”，并在任务结束、编辑窗口关闭、桌面可见后弹出可选的软件更新提醒。可选择“立即更新并重启”或“稍后”；不强制更新、不打断任务。Aplus自行安装的本机发行分支若已被正式main完整吸收，会自动迁移并保留受保护启动文件；普通开发分支、未吸收代码或其他修改仍禁用更新并说明需维护者核对。手动点顶栏按钮可立即重新检查，不受每日频率限制。

自动提醒按主线提交号记在 `.git/aplus-update/notice.json`，同一新版跨重启也不反复弹出；选择稍后仍可通过顶栏手动更新。窗口不锁住界面、不抢编辑焦点；托盘隐藏时等恢复后再提示，离线／CI未通过／没有新版不弹更新提醒。提醒本身不写交易数据、不预留更新任务，也不替用户确认。缓存结果不能直接升级时，会先要求重新检查。顶部“使用说明”可离线阅读完整操作规则。

“最新版”只指约定仓库 `sysujonathan/Aplus` 的main当前提交，且该提交最新一轮 `A acceptance` 的main push验收成功。未合并PR、失败／进行中的验收不能成为自动更新目标。本地包含未合并修复时显示“尚未进入主线”，不会回退到较旧main；分叉必须人工核对。本地有修改时提交号不能代表全部正在使用的代码。

显示的本地提交号来自磁盘Git状态。若通过命令行或人工复制在运行中修改过代码，必须从托盘退出并重开，不能把磁盘提交号当成尚未重启进程已加载全部新代码的证明。

本地分支、提交号及Git日志仅供维护核对；普通用户先看版本号与结论。确认“更新并重启”才会更新代码。每天的后台检查和弹出提醒不等于同意更新，重新确认时会重新核验目标及验收状态。

## 哪些情况不会直接PULL

- 行情、扫描、研究或状态核验任务仍在排队／运行／收尾。
- 持仓编辑、截图导入预览等弹窗还未关闭；先保存并关闭它们。
- 默认本地Web端口8517仍被占用或无法核对；先退出Web服务。

- 不是普通Git安装；或本机发行版以外的开发分支、有未吸收代码、其他未提交修改／新增文件及无法证明安全的分叉。
- 新文件会覆盖本地保留文件，或代码路径有链接／子模块。
- 新版涉及依赖，或改变数据库初始化／结构、已有保存逻辑、数据路径，及无法证明兼容的保存程序变化；要求人工升级验收。策略／配置变化只有匹配已核准的准确文件版本才可自动更新，其他变化仍需人工核对。
- Git、GitHub或网络检查失败，以及检查期间main又出现新提交。

本地端口确认等待最多3秒：Windows关闭端口可能约2秒才明确拒绝连接。只有明确“拒绝连接”才认可已关闭；连接成功、超时或其他无法确认的结果仍拒绝更新，不把延迟或网络异常当作已退出。

`store.py`不再只要整文件变化就禁用更新。检查器只读解析两个精确提交的代码，不运行候选代码、不打开业务数据库：模块初始化、数据路径、类结构及所有已有方法必须保持一致；唯一已验证的已有方法例外，是同目录原子写入的短临时文件名调整，其余写入、刷盘和替换语句不变。新增普通公开方法不能引入结构SQL、动态SQL、生命周期钩子或类定义时的可执行默认值／装饰器。无法解析、缺失旧文件、结构或已有保存行为变化等仍需人工安装，不能只凭schema版本号相同放行。该检查不是对所有新功能的绝对安全证明：依然要求官方main精确提交自检通过、隔离启动预检、原代码与本机启动文件备份、目标变化后复核。

已在 PR42 获批的 MTR V36.3 不再仅因改了策略文件就要求用户人工安装。更新器只认可这次限定的两个 MTR 文件：旧、新 SHA-256 必须与已审核的版本完全匹配，批准记录必须准确追加，完整新旧冻结清单与 Git 文件字节都须一致，其他保护文件、路径集合和基线来源不得变化。候选清单不能自行批准任意代码；缺少记录、改写校验值、夹带其他策略或配置变化仍停止更新。检查和执行时仍分别确认官方 main 的精确提交与最新自检通过，并进行隔离冻结校验、启动预检及旧代码备份。将来新的策略版本需在独立审核中补充准确版本许可及回归测试，不构成解除策略冻结红线。

旧版更新器自身若使用整文件拦截，会挡住获取这项修复；只合入新 PR 不能改变正在运行的旧检查器。此类旧安装需由维护者在完整退出后，使用通过测试的独立升级工具按同一套保护核对、备份、预检和更新到已验收主线；不能在运行中热改保护开关，也不能伪造自检通过。升级不重做行情／扫描、不清理运行数据。之后的新版本由软件内入口按实际兼容性判断。

剩余人工安装提示分别说明依赖／安装环境、数据保存兼容性或未核准策略／配置变化，不再混为笼统的“新版需要维护者验收”。自检等待与这三类阻断保持分开，详细文件信息仍收在技术详情，不把本机路径或异常原文展示给普通用户。

维护入口为`tools/maintenance_update.py`，只供维护者从已测试的代码目录运行，必须明确指定旧安装、原数据目录和原Python环境。它仍使用同一独立更新助手，不跳过准确main自检和兼容保护；存在未完成任务、事务日志或其他Aplus／Web进程时停止。原数据库额外备份到受保护的更新回执目录，替换代码前后核对64位SHA-256摘要，只有重启前字节保持一致才记该项验证通过。正常重启可能更新任务状态或界面偏好，不能拿重启后的整个数据库文件摘要冒充业务数据丢失；本轮测试和升级不会删除或回退账本。

本地保留文件保护按新旧提交的跟踪路径核对，覆盖新增、重命名及复制后的目标文件，不依赖Git把差异归为“新增”还是“改名”。即使文件被Git忽略，撞名仍停止更新；确认后及隔离预检完成后再次核对，不能凭旧检查结果覆盖后来出现的保留文件。

不会自动stash、强制reset、清理目录或安装依赖。对Aplus自行建立的 `codex/local-release-YYYYMMDD` 本机发行分支，更新器会虚拟合并当前提交与精确main目标：只有合并结果相对main不含运行代码差异时，才在独立保护进程中切换main并快进。历史说明、测试和显示用发布记录可由正式main取代，`push.cmd` 原样备份并恢复；尚未合并的功能代码、未知开发分支和其他本机修改不能因此被丢弃。

## 更新过程及数据边界

确认后Service先原子锁定空闲状态，阻止新的业务任务进入；窗口暂时隐藏。独立保护进程就绪后才退出旧桌面，并等待整个旧进程释放Windows单实例保护，绝不在旧进程运行中替换文件。保护进程未就绪则撤销这次许可、恢复原窗口；稍后退出程序不会让已取消的准备偷偷执行。

准备更新期间，托盘的打开／退出暂不执行，但监听继续；只有真正关闭程序才停止监听。准备失败或助手超时后，原窗口和托盘恢复正常，可再次打开界面或退出，不必结束进程来恢复。

先在临时代码目录和全新临时数据仓进行冻结校验、依赖导入及真实Tk桌面构建，再重新核验本地和远端状态，仅执行固定提交的快进更新。代码更新后再做隔离启动检查。正式重启固定使用原Store的运行目录，不因更新改变数据位置。桌面和后端实际启动回执到达才记“完成”，仅生成进程不算成功；启动尚未确认会明确记录，不强制杀进程。

更新元信息、保护锁、原提交代码压缩包和回执位于 `.git/aplus-update/`，不会写进交易数据库或提交Git。受保护的 `push.cmd` 也随旧代码备份保存。它们是代码恢复材料，不是个人数据备份。不删除行情、成交、持仓、资金流水和研究记录，也不回退正式数据库。隔离启动检查失败时停止或安全返回旧代码；本机发行版恢复原分支，普通main更新失败则返回旧提交的游离版本。出现上次保护锁时先检查回执，不盲目删除或反复更新。

首版仅针对单个Windows桌面服务。不能同时运行Web工作台／另一独立服务实例共享同一安装或数据仓；升级前先关闭这些入口。默认Web端口在确认和实际替换前均会核对，有服务监听或核对失败则拒绝；自行改端口的Web／自定义服务仍须主动退出，不以默认端口空闲冒充全机进程检查。代码与启动检查通过，不等于真实账户、真实行情或长期使用均已验收。若主线没有新提交，按钮不会凭空产生版本更新。

## 一键盘前遇到行情缺口

版本提示与行情门禁是两件事。三源同步仅部分完成但 `scan_readiness.scan_allowed` 明确允许时，一键盘前会继续扫描 `eligible_ids` 中的合格股票，问题标的不计算、保留缺口和部分完成回执；忽略提醒不放宽资格。目录／日历等范围核验失败、全部标的受未解决缺口阻断、同步失败或用户终止时，不自动继续。若全体均确认当日停牌，可进入扫描核验但回执为“没有可扫描股票”，不计算策略。扫描阶段仍重新进行本地完整性校验，不以同步回执代替真正的扫描门禁。
