# 启动器编码修复（双击 启动A.vbs 报 800A0401）

## 现象

双击 `启动A.vbs` 弹出 Windows Script Host 错误：

```
脚本: D:\HL\Trip\A\启动A.vbs
行:   28  字符: 94
错误: 语句未结束
代码: 800A0401（Microsoft VBScript 编译器错误）
```

窗口直接关掉，程序起不来。`启动A.cmd` 不受影响。

## 根因

`wscript` / `cscript` 解析 `.vbs` 时按**系统代码页（本机 cp936 / GBK）**读取，**不识别 UTF-8**。而该文件在 `3c213ed Aplus：补齐自动更新中断恢复` 被写入了中文提示，且以 **UTF-8 无 BOM** 存盘。

于是引擎把 UTF-8 的中文字节按 GBK 解码：一个三字节汉字变成一到两个乱码字符，字节对齐整体错位，**第 28 行那个 MsgBox 的收尾双引号被当作 GBK 尾字节吞掉**，字符串永不闭合 → 该行在字符 94 处「语句未结束」。

各版本对照（`git show <rev>:启动A.vbs` 的字节统计）：

| 提交 | 字节 | 非 ASCII 字节 | 结果 |
|---|---|---|---|
| `f3f4c42`（PR #78 之前） | 644 | 0 | 纯 ASCII，正常 |
| `82d6d4e`（PR #78 自动更新事务） | 1162 | 0 | 仍纯 ASCII，正常 |
| `3c213ed`（补自动更新中断恢复） | 2451 | 255 | 引入中文 + UTF-8，坏 |
| 合并后 HEAD | 2451 | 255 | 与 main 一致，坏 |

`启动A.cmd` 同批被改到 1586 字节，但**非 ASCII 仍为 0**，所以照旧可用。

## 改法

**只改字节编码，不动一行逻辑**：把 `启动A.vbs` 以 **GBK（cp936）** 重新存盘，保留原有 LF 行尾。文件顶部加三行纯 ASCII 注释，写明这个文件不能存成 UTF-8。

为什么选 GBK 而不是别的：

| 方案 | 中文显示 | git 可 diff | 再被改坏的风险 | 说明 |
|---|---|---|---|---|
| **GBK（本次采用）** | ✓ | ✓ | 中 | 改动最小，仍是文本，wscript 原生读法 |
| UTF-8 + BOM | ✗ | ✗ | — | wscript 不认 UTF-8 BOM，照样乱码 |
| UTF-16 LE + BOM | ✓ | ✗（二进制） | 低 | 自描述，但 git 视为二进制、无法 review |
| 全英文提示 | ✗ | ✓ | 无 | 最保险，但丢中文提示 |

选 GBK 的直接理由：这台机器的唯一消费者是中文 Windows 的 `wscript`，cp936 是它的原生编码；文件仍是可 diff 的文本，只有两行字面量的字节变了。

## 防复发

新增回归 `tests/test_desktop_layout.py::test_windows_launchers_are_never_saved_as_utf8`：

- 纯 ASCII 的启动器一律放行；
- 含非 ASCII 的，**只要能按 UTF-8 解码就判失败**——那正是 wscript 会读成乱码的形态；
- 再要求能按 cp936 解出且无替换字符。

同时把两处按 `utf-8` 读启动器的既有测试改成 `cp936`：

- `tests/test_desktop_layout.py::test_windows_launchers_forward_persisted_runtime_home`
- `tests/test_version_update.py::test_launchers_prefer_committed_environment_pointer_without_configuring_users`

这两处原本假设文件是 UTF-8，等于把错误编码写进了测试。

## 不影响的东西

- 启动逻辑一行未改：注册表 `A_WORKBENCH_HOME` 继承、更新事务恢复、`current-python.txt` 指针、`pythonw` 拉起 `launch_dashboard.py`，全部原样。
- 自更新链路安全：`workbench/version_update.py` 的 `_clean_preserved()` 用 `git show ... binary=True` 取原始字节，不做编码转换，GBK 字节原样落地。
- `启动A.cmd` 未改。

## 验收

- `tests/test_version_update.py` + `tests/test_desktop_layout.py`：**136 passed**
- 静态回读：把新文件按 cp936 解码、剥掉 3 行守卫注释后，**与 main 版本逐字符完全一致**（只改字节，不改文本）；逐行双引号全部成对；cp936 解码零替换字符。
- 未做：本机 `cscript`/`wscript` 被安全策略拦截，无法直接编译验证，需人工双击 `启动A.vbs` 确认窗口正常打开。
